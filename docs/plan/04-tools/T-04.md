# T-04 · `get_attempt_history` — 연습 이력·실제 개입 조회

[도구 목록](README.md) · [공통 결과](../05-contracts/common-result.md) · [명령 프로토콜](../05-contracts/command-protocol.md)

## 1. 목적·호출 경계

현재 목적과 관련 있는 이전 시도와 실제 적용·거절·불명 개입을 조회한다.

- 모드: `read`
- 연결된 세부 계약: [S-08](../03-small-nodes/S-08.md) · [S-15](../03-small-nodes/S-15.md)
- 제한: 원본 영상·모든 이벤트를 한 번에 반환하지 않는다. 깊은 조회는 근거 ID로 제한한다.
- 모든 예시 값은 구조 설명용이며 측정 결과가 아니다.

## 2. 호출 전제와 권한

- 기본 범위는 현재 세션에 제한한다.
- 장기 개인화는 별도 사용자 식별·보관 정책을 정한 뒤 확장한다.

세션·시도 범위, snapshot_ref, tool_call_id, 버전·예산은 하네스가 검증한다. 모델의 reason 문장은 권한·유효성의 증거를 대체하지 않는다.

## 3. 모델 입력 인자

| 인자 | 타입 | 필수 | 의미 |
| --- | --- | --- | --- |
| limit | integer | 아니요 | 최신 순 조회 개수. 설계상 최대 20, 기본 5 |
| scope | string | 아니요 | 조회 범위 |

### JSON Schema

```json
{
  "type": "object",
  "properties": {
    "limit": {
      "type": "integer",
      "description": "최신 순 조회 개수. 설계상 최대 20, 기본 5",
      "minimum": 1,
      "maximum": 20,
      "default": 5
    },
    "scope": {
      "type": "string",
      "description": "조회 범위",
      "minLength": 1,
      "enum": [
        "same_range",
        "same_exercise",
        "session"
      ],
      "default": "same_range"
    }
  },
  "required": [],
  "additionalProperties": false
}
```

### 호출 예시

```json
{
  "name": "get_attempt_history",
  "arguments": {
    "limit": 3,
    "scope": "same_range"
  }
}
```

범위·버전·두 필드 간 관계·운영 한도는 스키마 외의 의미 검증으로 확인한다. 파싱 성공만으로 실행 가능하다고 판단하지 않는다.

## 4. 내부 함수와 처리 순서

| 함수 | 입력 | 책임 |
| --- | --- | --- |
| resolve_history_scope | 컨텍스트·scope | 조회 범위 |
| query_attempt_records | 범위·limit | 시도 목록 |
| attach_intervention_lifecycle | 시도·개입 ID | 요청/실제 설정·상태 |

1. 요청 범위와 반환 개수 상한을 검사한다.
2. 동일 범위·곡의 기록을 최신 순으로 조회한다.
3. 실제 설정과 개입 수명주기를 함께 반환한다.

## 5. 반환 계약과 예시

반환 타입: `NodeResult[AttemptHistory]`. 진단은 실제 수행한 단계별로 기록한다. 다음 예시는 대표 필드만 보여준다.

```json
{
  "status": "success",
  "data": {
    "items": [
      {
        "attempt_id": "a02",
        "snapshot_ref": "snap-a02",
        "input_source": "camera_pose",
        "bpm": 80,
        "range_ref": "range-01",
        "intervention_ref": "int-02",
        "intervention_lifecycle": "applied"
      },
      {
        "attempt_id": "a01",
        "snapshot_ref": "snap-a01",
        "input_source": "camera_pose",
        "bpm": 80,
        "range_ref": "range-01",
        "intervention_ref": null
      }
    ],
    "returned_count": 2,
    "order": "newest_first",
    "truncated": false
  },
  "diagnostics": {
    "resolve_history_scope": {
      "status": "success"
    }
  },
  "outcome": "result_available"
}
```

목록이 없거나 비교 근거가 부족한 정상 결과와 저장소·모델 실행 실패를 구분한다. 반환할 수 없는 수치는 null과 사유로 남긴다. 실제 조회·계산 과정과 결과 ID를 진단·근거로 연결한다.

## 6. 실패·보류 처리

| 코드 | 조건 | 처리 |
| --- | --- | --- |
| INVALID_LIMIT | 허용 범위 밖 조회량 | 유효 limit으로 재호출 |
| HISTORY_READ_FAILED | 저장소 읽기 실패 | 예산 내 읽기 재시도 |
| HISTORY_SCOPE_VIOLATION | 허용 세션 밖 | 거절 |

업무상 정보 부족·정상 대기는 `status=success`와 별도 outcome으로 반환할 수 있다. 실행 실패는 `error`, 안전한 일부 결과를 보존할 때만 `partial`이다. 오류 코드는 `diagnostics`에, 업무 결과는 `outcome`에 둔다.

## 7. 부작용·멱등성·재시도

사용자 연습 설정을 변경하지 않는다. 조회 재시도는 동일 snapshot_ref·조회 범위를 유지한다. 로그·캐시는 허용하지만 다른 시점의 결과로 바뀌었다면 snapshot·freshness를 명시한다.

일시적 실행 오류는 공통 예산 내에서만 재시도한다. 범위·버전·사용자 의사 위반은 동일 입력으로 반복하지 않는다. 단계별 시간과 토큰·호출 사용량은 [하네스](../06-harness-and-evaluation.md)가 기록한다.

## 8. 검증 사례

- 빈 이력은 정상 빈 목록이다.
- 실패한 저장소 읽기를 이력 없음으로 바꾸지 않는다.
- 오래된 queued 명령이 성공 개입으로 표시되지 않는다.

## 9. 확인할 로그

`run_id`, `context_id`, `tool_call_id`, 도구·계약 버전, 요청 snapshot_ref, 입력 인자, 결과·근거 ID, status·outcome, 지연, 예산 사용량을 남긴다. 변경 도구는 proposal_id에서 command_id·ACK·intervention_id까지 연결한다.

이 문서는 계획 명세다. 특정 모델이나 라이브러리의 자동 실행 기능을 전제로 하지 않으며 현재 구현 진척을 기록하지 않는다.
