# T-06 · `get_reference_excerpt` — 기대 악보 구간 조회

[도구 목록](README.md) · [공통 결과](../05-contracts/common-result.md) · [명령 프로토콜](../05-contracts/command-protocol.md)

## 1. 목적·호출 경계

현재 연습곡의 요청 범위에 있는 기대 음·박자·마디 표기와 지원 기능을 조회한다.

- 모드: `read`
- 연결된 세부 계약: [S-07](../03-small-nodes/S-07.md) · [S-10](../03-small-nodes/S-10.md)
- 제한: 외부 곡 검색·음원 전사·악보 저작권 판단 도구는 이 계약에 포함하지 않는다.
- 모든 예시 값은 구조 설명용이며 측정 결과가 아니다.

## 2. 호출 전제와 권한

- 곡 참조는 현재 세션에 바인딩한다.
- 손 분리·음 길이처럼 지원되지 않는 기능은 capabilities에 넣지 않는다.

세션·시도 범위, snapshot_ref, tool_call_id, 버전·예산은 하네스가 검증한다. 모델의 reason 문장은 권한·유효성의 증거를 대체하지 않는다.

## 3. 모델 입력 인자

| 인자 | 타입 | 필수 | 의미 |
| --- | --- | --- | --- |
| start_index | integer | 예 | 시작 음표 인덱스, 포함 |
| end_index | integer | 예 | 끝 음표 인덱스, 포함 |

### JSON Schema

```json
{
  "type": "object",
  "properties": {
    "start_index": {
      "type": "integer",
      "description": "시작 음표 인덱스, 포함",
      "minimum": 0
    },
    "end_index": {
      "type": "integer",
      "description": "끝 음표 인덱스, 포함",
      "minimum": 0
    }
  },
  "required": [
    "start_index",
    "end_index"
  ],
  "additionalProperties": false
}
```

### 호출 예시

```json
{
  "name": "get_reference_excerpt",
  "arguments": {
    "start_index": 0,
    "end_index": 2
  }
}
```

범위·버전·두 필드 간 관계·운영 한도는 스키마 외의 의미 검증으로 확인한다. 파싱 성공만으로 실행 가능하다고 판단하지 않는다.

## 4. 내부 함수와 처리 순서

| 함수 | 입력 | 책임 |
| --- | --- | --- |
| resolve_bound_exercise | 세션 곡 참조 | 정확한 곡 버전 |
| slice_score_range | 인덱스 범위 | 기대 음표 |
| describe_supported_capabilities | 곡·UI 계약 | 사용 가능한 설명·도구 범위 |

1. 곡·버전·요청 범위를 확인한다.
2. 고정된 기대 음표와 표기·지원 범위를 반환한다.
3. 이 데이터가 관측 음이 아닌 기대 음임을 명시한다.

## 5. 반환 계약과 예시

반환 타입: `NodeResult[ExerciseExcerpt]`. 진단은 실제 수행한 단계별로 기록한다. 다음 예시는 대표 필드만 보여준다.

```json
{
  "status": "success",
  "data": {
    "exercise_ref": "exercise-demo-v1",
    "range": {
      "start_index": 0,
      "end_index": 2
    },
    "notes": [
      {
        "index": 0,
        "midi_note": 60,
        "beats": 1,
        "measure": 1
      },
      {
        "index": 1,
        "midi_note": 64,
        "beats": 1,
        "measure": 1
      },
      {
        "index": 2,
        "midi_note": 67,
        "beats": 1,
        "measure": 1
      }
    ],
    "supported_capabilities": [
      "virtual_note",
      "onset_timing"
    ],
    "reference_role": "expected_only"
  },
  "diagnostics": {
    "resolve_bound_exercise": {
      "status": "success"
    }
  },
  "outcome": "result_available"
}
```

목록이 없거나 비교 근거가 부족한 정상 결과와 저장소·모델 실행 실패를 구분한다. 반환할 수 없는 수치는 null과 사유로 남긴다. 실제 조회·계산 과정과 결과 ID를 진단·근거로 연결한다.

## 6. 실패·보류 처리

| 코드 | 조건 | 처리 |
| --- | --- | --- |
| INVALID_SCORE_RANGE | 곡 범위 밖 | 유효 범위로 수정 |
| REFERENCE_UNAVAILABLE | 허용된 악보 정보 없음 | 악보 정보 부족으로 보류 |
| UNSUPPORTED_CAPABILITY | 정의되지 않은 악보·손 정보 | 임의 생성 금지 |

업무상 정보 부족·정상 대기는 `status=success`와 별도 outcome으로 반환할 수 있다. 실행 실패는 `error`, 안전한 일부 결과를 보존할 때만 `partial`이다. 오류 코드는 `diagnostics`에, 업무 결과는 `outcome`에 둔다.

## 7. 부작용·멱등성·재시도

사용자 연습 설정을 변경하지 않는다. 조회 재시도는 동일 snapshot_ref·조회 범위를 유지한다. 로그·캐시는 허용하지만 다른 시점의 결과로 바뀌었다면 snapshot·freshness를 명시한다.

일시적 실행 오류는 공통 예산 내에서만 재시도한다. 범위·버전·사용자 의사 위반은 동일 입력으로 반복하지 않는다. 단계별 시간과 토큰·호출 사용량은 [하네스](../06-harness-and-evaluation.md)가 기록한다.

## 8. 검증 사례

- 기대 음을 관측 이벤트로 출력하지 않는다.
- 음표 인덱스와 마디 번호를 구분한다.
- 정의되지 않은 왼손·오른손 분리를 만들어내지 않는다.

## 9. 확인할 로그

`run_id`, `context_id`, `tool_call_id`, 도구·계약 버전, 요청 snapshot_ref, 입력 인자, 결과·근거 ID, status·outcome, 지연, 예산 사용량을 남긴다. 변경 도구는 proposal_id에서 command_id·ACK·intervention_id까지 연결한다.

이 문서는 계획 명세다. 특정 모델이나 라이브러리의 자동 실행 기능을 전제로 하지 않으며 현재 구현 진척을 기록하지 않는다.
