# T-01 · `get_practice_state` — 연습 상태 조회

[도구 목록](README.md) · [공통 결과](../05-contracts/common-result.md) · [명령 프로토콜](../05-contracts/command-protocol.md)

## 1. 목적·호출 경계

현재 판단에 연결된 불변 스냅샷과 실제 설정·진행 단계를 조회한다.

- 모드: `read`
- 연결된 세부 계약: [S-08](../03-small-nodes/S-08.md) · [S-10](../03-small-nodes/S-10.md)
- 제한: 모든 프레임을 반환하지 않는다. 지표 상세는 근거 참조나 다른 조회 도구로 가져온다.
- 모든 예시 값은 구조 설명용이며 측정 결과가 아니다.

## 2. 호출 전제와 권한

- 활성 세션은 하네스 컨텍스트에 묶여 있어야 한다.
- 기본 조회는 현재 코칭 context의 스냅샷이며 latest 여부와 freshness를 반환한다.

세션·시도 범위, snapshot_ref, tool_call_id, 버전·예산은 하네스가 검증한다. 모델의 reason 문장은 권한·유효성의 증거를 대체하지 않는다.

## 3. 모델 입력 인자

모델 인자는 없다. 세션·판단 범위는 하네스 컨텍스트에 바인딩한다.

### JSON Schema

```json
{
  "type": "object",
  "properties": {},
  "required": [],
  "additionalProperties": false
}
```

### 호출 예시

```json
{
  "name": "get_practice_state",
  "arguments": {}
}
```

범위·버전·두 필드 간 관계·운영 한도는 스키마 외의 의미 검증으로 확인한다. 파싱 성공만으로 실행 가능하다고 판단하지 않는다.

## 4. 내부 함수와 처리 순서

| 함수 | 입력 | 책임 |
| --- | --- | --- |
| resolve_bound_session | 컨텍스트 | 허용 세션 |
| read_coach_snapshot | snapshot_ref | 불변 판단 상태 |
| attach_live_control_metadata | 실제 제어 상태 | 변경 여부·freshness |

1. 컨텍스트의 세션과 snapshot_ref를 해석한다.
2. 불변 스냅샷과 현재 제어 버전을 함께 읽는다.
3. 대기 중 명령과 실제 적용 상태를 구분해 반환한다.

## 5. 반환 계약과 예시

반환 타입: `NodeResult[PracticeSnapshot]`. 진단은 실제 수행한 단계별로 기록한다. 다음 예시는 대표 필드만 보여준다.

```json
{
  "status": "success",
  "data": {
    "snapshot_id": "snap-a03",
    "state_version": 12,
    "session_phase": "between_attempts",
    "actual_config": {
      "bpm": 80,
      "start_index": 0,
      "end_index": 7,
      "hint_level": 2,
      "config_version": 4
    },
    "observation_status": "usable_provisional",
    "contact_verified": false,
    "evidence_refs": [
      "metrics-a03",
      "quality-a03"
    ]
  },
  "diagnostics": {
    "resolve_bound_session": {
      "status": "success"
    }
  },
  "outcome": "result_available"
}
```

목록이 없거나 비교 근거가 부족한 정상 결과와 저장소·모델 실행 실패를 구분한다. 반환할 수 없는 수치는 null과 사유로 남긴다. 실제 조회·계산 과정과 결과 ID를 진단·근거로 연결한다.

## 6. 실패·보류 처리

| 코드 | 조건 | 처리 |
| --- | --- | --- |
| SNAPSHOT_UNAVAILABLE | 평가 가능한 상태가 아직 없음 | 추가 관측을 요청하고 수치를 만들지 않음 |
| STALE_CONTEXT | 판단 중 세션·기준 변경 | 최신 트리거로 재판단 |
| SESSION_SCOPE_VIOLATION | 다른 세션 참조 | 재시도 없이 거절 |

업무상 정보 부족·정상 대기는 `status=success`와 별도 outcome으로 반환할 수 있다. 실행 실패는 `error`, 안전한 일부 결과를 보존할 때만 `partial`이다. 오류 코드는 `diagnostics`에, 업무 결과는 `outcome`에 둔다.

## 7. 부작용·멱등성·재시도

사용자 연습 설정을 변경하지 않는다. 조회 재시도는 동일 snapshot_ref·조회 범위를 유지한다. 로그·캐시는 허용하지만 다른 시점의 결과로 바뀌었다면 snapshot·freshness를 명시한다.

일시적 실행 오류는 공통 예산 내에서만 재시도한다. 범위·버전·사용자 의사 위반은 동일 입력으로 반복하지 않는다. 단계별 시간과 토큰·호출 사용량은 [하네스](../06-harness-and-evaluation.md)가 기록한다.

## 8. 검증 사례

- 아직 없는 지표를 0으로 반환하지 않는다.
- staged·queued 설정을 actual_config로 반환하지 않는다.
- 모델 입력 중 변경 사실이 freshness에 표시된다.

## 9. 확인할 로그

`run_id`, `context_id`, `tool_call_id`, 도구·계약 버전, 요청 snapshot_ref, 입력 인자, 결과·근거 ID, status·outcome, 지연, 예산 사용량을 남긴다. 변경 도구는 proposal_id에서 command_id·ACK·intervention_id까지 연결한다.

이 문서는 계획 명세다. 특정 모델이나 라이브러리의 자동 실행 기능을 전제로 하지 않으며 현재 구현 진척을 기록하지 않는다.
