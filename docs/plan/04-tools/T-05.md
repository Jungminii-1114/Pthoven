# T-05 · `compare_attempts` — 시도 조건과 변화 비교

[도구 목록](README.md) · [공통 결과](../05-contracts/common-result.md) · [명령 프로토콜](../05-contracts/command-protocol.md)

## 1. 목적·호출 경계

두 시도의 비교 가능 조건과 계산된 변화량을 조회하여 다음 연습 선택의 근거로 사용한다.

- 모드: `read`
- 연결된 세부 계약: [S-16](../03-small-nodes/S-16.md) · [S-17](../03-small-nodes/S-17.md)
- 제한: 이 도구는 읽기·계산 전용이다. 개선 판정이 곧바로 자동 템포 증가를 실행하지 않는다.
- 모든 예시 값은 구조 설명용이며 측정 결과가 아니다.

## 2. 호출 전제와 권한

- 두 시도가 같은 허용 세션에 속해야 한다.
- 실제 적용 조건과 평가 가능한 지표가 있어야 한다.

세션·시도 범위, snapshot_ref, tool_call_id, 버전·예산은 하네스가 검증한다. 모델의 reason 문장은 권한·유효성의 증거를 대체하지 않는다.

## 3. 모델 입력 인자

| 인자 | 타입 | 필수 | 의미 |
| --- | --- | --- | --- |
| before_attempt_id | string | 예 | 비교 기준 시도 ID |
| after_attempt_id | string | 예 | 비교할 이후 시도 ID |

### JSON Schema

```json
{
  "type": "object",
  "properties": {
    "before_attempt_id": {
      "type": "string",
      "description": "비교 기준 시도 ID",
      "minLength": 1
    },
    "after_attempt_id": {
      "type": "string",
      "description": "비교할 이후 시도 ID",
      "minLength": 1
    }
  },
  "required": [
    "before_attempt_id",
    "after_attempt_id"
  ],
  "additionalProperties": false
}
```

### 호출 예시

```json
{
  "name": "compare_attempts",
  "arguments": {
    "before_attempt_id": "a02",
    "after_attempt_id": "a03"
  }
}
```

범위·버전·두 필드 간 관계·운영 한도는 스키마 외의 의미 검증으로 확인한다. 파싱 성공만으로 실행 가능하다고 판단하지 않는다.

## 4. 내부 함수와 처리 순서

| 함수 | 입력 | 책임 |
| --- | --- | --- |
| load_attempt_pair | 두 시도 ID | 불변 스냅샷 |
| check_comparability | 두 조건·정책 | 비교 범위 |
| compute_comparison | 유효 지표 쌍 | 변화·제한·근거 |

1. S-16 계약으로 비교 축과 제외 사유를 만든다.
2. S-17 계약으로 유효한 값만 차이를 계산한다.
3. 동일 조건·변경 조건·비교 불가를 구분해 반환한다.

## 5. 반환 계약과 예시

반환 타입: `NodeResult[InterventionComparison]`. 진단은 실제 수행한 단계별로 기록한다. 다음 예시는 대표 필드만 보여준다.

```json
{
  "status": "success",
  "data": {
    "before_attempt_id": "a02",
    "after_attempt_id": "a03",
    "comparison_scope": "changed_conditions",
    "condition_differences": [
      {
        "field": "bpm",
        "before": 80,
        "after": 60
      }
    ],
    "metric_deltas": [
      {
        "metric": "matched_note_ratio",
        "before": 0.75,
        "after": 0.875,
        "delta": 0.125,
        "unit": "ratio"
      }
    ],
    "interpretation_limit": "낮춘 템포에서의 가상 입력 변화이며 원래 템포의 능력 향상은 확인하지 않음",
    "evidence_refs": [
      "snap-a02",
      "snap-a03"
    ]
  },
  "diagnostics": {
    "load_attempt_pair": {
      "status": "success"
    }
  },
  "outcome": "result_available"
}
```

목록이 없거나 비교 근거가 부족한 정상 결과와 저장소·모델 실행 실패를 구분한다. 반환할 수 없는 수치는 null과 사유로 남긴다. 실제 조회·계산 과정과 결과 ID를 진단·근거로 연결한다.

## 6. 실패·보류 처리

| 코드 | 조건 | 처리 |
| --- | --- | --- |
| ATTEMPT_NOT_FOUND | 한 시도 없음 | 범위 내 실제 ID 조회 |
| COMPARISON_UNAVAILABLE | 안전한 비교 축 없음 | 업무 결과 not_comparable로 보류 |
| EVIDENCE_VERSION_MISMATCH | 지표 정의·버전 불일치 | 변화 계산 금지 |

업무상 정보 부족·정상 대기는 `status=success`와 별도 outcome으로 반환할 수 있다. 실행 실패는 `error`, 안전한 일부 결과를 보존할 때만 `partial`이다. 오류 코드는 `diagnostics`에, 업무 결과는 `outcome`에 둔다.

## 7. 부작용·멱등성·재시도

사용자 연습 설정을 변경하지 않는다. 조회 재시도는 동일 snapshot_ref·조회 범위를 유지한다. 로그·캐시는 허용하지만 다른 시점의 결과로 바뀌었다면 snapshot·freshness를 명시한다.

일시적 실행 오류는 공통 예산 내에서만 재시도한다. 범위·버전·사용자 의사 위반은 동일 입력으로 반복하지 않는다. 단계별 시간과 토큰·호출 사용량은 [하네스](../06-harness-and-evaluation.md)가 기록한다.

## 8. 검증 사례

- 다른 BPM 결과를 동일 난이도 향상으로 표현하지 않는다.
- 한쪽 null을 0으로 채우지 않는다.
- 비교 조회가 게임 설정을 변경하지 않는다.

## 9. 확인할 로그

`run_id`, `context_id`, `tool_call_id`, 도구·계약 버전, 요청 snapshot_ref, 입력 인자, 결과·근거 ID, status·outcome, 지연, 예산 사용량을 남긴다. 변경 도구는 proposal_id에서 command_id·ACK·intervention_id까지 연결한다.

이 문서는 계획 명세다. 특정 모델이나 라이브러리의 자동 실행 기능을 전제로 하지 않으며 현재 구현 진척을 기록하지 않는다.
