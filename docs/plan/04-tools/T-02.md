# T-02 · `get_segment_evidence` — 구간 오류·정렬 근거 조회

[도구 목록](README.md) · [공통 결과](../05-contracts/common-result.md) · [명령 프로토콜](../05-contracts/command-protocol.md)

## 1. 목적·호출 경계

특정 시도·음표 구간에서 어떤 입력·정렬·평가 보류가 발생했는지 조회한다.

- 모드: `read`
- 연결된 세부 계약: [S-07](../03-small-nodes/S-07.md) · [S-08](../03-small-nodes/S-08.md)
- 제한: 틀린 원인을 신체·기술 진단으로 반환하지 않는다. 사건·정렬의 관측 사실만 제공한다.
- 모든 예시 값은 구조 설명용이며 측정 결과가 아니다.

## 2. 호출 전제와 권한

- 범위가 해당 exercise_version 안에 있고 start_index <= end_index여야 한다.
- 관측 가능한 오류와 unknown 제외 구간을 모두 반환한다.

세션·시도 범위, snapshot_ref, tool_call_id, 버전·예산은 하네스가 검증한다. 모델의 reason 문장은 권한·유효성의 증거를 대체하지 않는다.

## 3. 모델 입력 인자

| 인자 | 타입 | 필수 | 의미 |
| --- | --- | --- | --- |
| attempt_id | string | 예 | 같은 세션의 시도 ID |
| start_index | integer | 예 | 곡 기준 시작 음표 인덱스, 포함 |
| end_index | integer | 예 | 곡 기준 끝 음표 인덱스, 포함 |

### JSON Schema

```json
{
  "type": "object",
  "properties": {
    "attempt_id": {
      "type": "string",
      "description": "같은 세션의 시도 ID",
      "minLength": 1
    },
    "start_index": {
      "type": "integer",
      "description": "곡 기준 시작 음표 인덱스, 포함",
      "minimum": 0
    },
    "end_index": {
      "type": "integer",
      "description": "곡 기준 끝 음표 인덱스, 포함",
      "minimum": 0
    }
  },
  "required": [
    "attempt_id",
    "start_index",
    "end_index"
  ],
  "additionalProperties": false
}
```

### 호출 예시

```json
{
  "name": "get_segment_evidence",
  "arguments": {
    "attempt_id": "a03",
    "start_index": 0,
    "end_index": 7
  }
}
```

범위·버전·두 필드 간 관계·운영 한도는 스키마 외의 의미 검증으로 확인한다. 파싱 성공만으로 실행 가능하다고 판단하지 않는다.

## 4. 내부 함수와 처리 순서

| 함수 | 입력 | 책임 |
| --- | --- | --- |
| validate_segment_scope | 시도·범위 | 허용 구간 |
| load_alignment_slice | alignment_ref·범위 | 정렬 항목 |
| bind_input_and_quality_refs | 정렬 항목 | 이벤트·품질 참조 |

1. 시도·곡 버전·범위 접근을 검사한다.
2. 정렬 기록에서 요청 범위를 추출한다.
3. 오류 종류·분모·제외 수·원본 이벤트 참조를 반환한다.

## 5. 반환 계약과 예시

반환 타입: `NodeResult[SegmentEvidence]`. 진단은 실제 수행한 단계별로 기록한다. 다음 예시는 대표 필드만 보여준다.

```json
{
  "status": "success",
  "data": {
    "attempt_id": "a03",
    "range": {
      "start_index": 0,
      "end_index": 7
    },
    "evaluable_count": 8,
    "excluded_count": 0,
    "matched_count": 6,
    "wrong_count": 2,
    "missed_count": 0,
    "extra_count": 0,
    "input_source": "camera_pose",
    "contact_verified": false,
    "alignment_ref": "align-a03",
    "event_refs": [
      "evt-01",
      "evt-02"
    ],
    "quality_ref": "quality-a03"
  },
  "diagnostics": {
    "validate_segment_scope": {
      "status": "success"
    }
  },
  "outcome": "result_available"
}
```

목록이 없거나 비교 근거가 부족한 정상 결과와 저장소·모델 실행 실패를 구분한다. 반환할 수 없는 수치는 null과 사유로 남긴다. 실제 조회·계산 과정과 결과 ID를 진단·근거로 연결한다.

## 6. 실패·보류 처리

| 코드 | 조건 | 처리 |
| --- | --- | --- |
| INVALID_SCORE_RANGE | 인덱스가 뒤집히거나 범위 밖 | 새로운 유효 범위로만 재호출 |
| ALIGNMENT_UNAVAILABLE | 정렬을 구성할 근거 없음 | 정보 부족으로 반환 |
| EVIDENCE_MISMATCH | 곡·이벤트 버전 불일치 | 근거 재구성 전 사용 보류 |

업무상 정보 부족·정상 대기는 `status=success`와 별도 outcome으로 반환할 수 있다. 실행 실패는 `error`, 안전한 일부 결과를 보존할 때만 `partial`이다. 오류 코드는 `diagnostics`에, 업무 결과는 `outcome`에 둔다.

## 7. 부작용·멱등성·재시도

사용자 연습 설정을 변경하지 않는다. 조회 재시도는 동일 snapshot_ref·조회 범위를 유지한다. 로그·캐시는 허용하지만 다른 시점의 결과로 바뀌었다면 snapshot·freshness를 명시한다.

일시적 실행 오류는 공통 예산 내에서만 재시도한다. 범위·버전·사용자 의사 위반은 동일 입력으로 반복하지 않는다. 단계별 시간과 토큰·호출 사용량은 [하네스](../06-harness-and-evaluation.md)가 기록한다.

## 8. 검증 사례

- unknown 구간의 무입력을 missed_count에 넣지 않는다.
- 다른 입력 출처의 오류 수를 합산하지 않는다.
- 문장 요약과 원본 정렬 수치가 일치한다.

## 9. 확인할 로그

`run_id`, `context_id`, `tool_call_id`, 도구·계약 버전, 요청 snapshot_ref, 입력 인자, 결과·근거 ID, status·outcome, 지연, 예산 사용량을 남긴다. 변경 도구는 proposal_id에서 command_id·ACK·intervention_id까지 연결한다.

이 문서는 계획 명세다. 특정 모델이나 라이브러리의 자동 실행 기능을 전제로 하지 않으며 현재 구현 진척을 기록하지 않는다.
