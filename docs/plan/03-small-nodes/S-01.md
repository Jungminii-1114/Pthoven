# S-01 · `prepare_session` — 세션과 입력 환경 준비

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

사용자가 선택한 장치·입력 모드·연습곡을 하나의 세션 범위와 초기 설정으로 고정한다.

- 실행 성격: **결정론적**
- 협업 담당: 웹·서버
- 범위 제외: 손가락 보정·음 매핑·연습 전략 선택은 수행하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `prepare_session(request, context) -> NodeResult[SessionContext]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| validate_session_request | 사용자 선택·정책 | 곡·범위·입력 모드 검사 |
| open_selected_camera | 명시한 장치 ID | 실제 활성 트랙 또는 장치 오류 |
| separate_video_and_tracker_state | 스트림·모델 준비 이벤트 | 영상·추론 준비 상태 분리 |
| initialize_session_versions | 세션 설정 | 초기 버전·단조 시계·실행 소유자 설정 |

## 3. 내부 처리 순서

1. 입력 출처를 camera_pose / keyboard / screen_pointer / replay로 구분한다.
2. 영상 연결·새 프레임 수신·추적기 준비 상태를 각각 보존한다.
3. 사용자가 고른 장치가 실패하면 다른 카메라로 조용히 바꾸지 않는다.
4. 세션 ID와 command_epoch를 발급하고 입력 버퍼·설정 기준을 초기화한다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| SessionStartRequest | 장치 선택, 입력 모드, 연습곡·범위, 화면 반전 선택 |
| SessionPolicy | 허용 입력·설정 범위, 관측·호출 예산 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[SessionContext]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `SessionContext`
- 보존할 업무 필드: `session_id, input_source, exercise_ref, clock_id, lifecycle_phase, config_version, command_epoch, device_state`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| ready_for_observation | 필수 세션 정보와 선택 장치 준비 |
| waiting_for_permission | 권한·사용자 응답 대기 |
| unsupported_input | 지원하지 않는 모드 |
| session_unavailable | 장치 또는 세션 준비 실패 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 권한이 없을 때 ready를 반환하지 않는다.
- 모델 준비 실패가 연결된 프리뷰를 종료하지 않는다.
- 카메라를 다시 연결하면 이전 프레임·명령 epoch를 재사용하지 않는다.
- 키보드 입력을 camera_pose로 표시하지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
