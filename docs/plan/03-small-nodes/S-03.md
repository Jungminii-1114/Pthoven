# S-03 · `calibrate_geometry_and_pose` — 가상 건반과 손가락 기준 보정

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

표시 좌표 변환과 기준·들림 자세를 검증하여 버전이 있는 CalibrationBundle을 만든다.

- 실행 성격: **결정론적**
- 협업 담당: CV·웹
- 범위 제외: 실제 건반·아이패드 인식이나 센서 기반 높이 보정은 필수 범위에 넣지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `calibrate_geometry_and_pose(request, context) -> NodeResult[CalibrationBundle]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| validate_calibration_samples | 기준·들림 샘플 | 관측 수·안정성·자세 차이 검사 |
| build_display_transform | 영상·화면 크기·반전 | 단일 좌표 변환 |
| fit_finger_templates | 유효한 자세 특징 | 손가락별 보정 템플릿 |
| publish_calibration_version | 검증된 템플릿·기하 | 새 버전과 기존 상태 무효화 범위 |

## 3. 내부 처리 순서

1. 좌표 변환과 자세 보정을 구분해 수집한다.
2. 기준·들림 자세 차이가 불충분하거나 흔들리면 다시 수집한다.
3. 표시 변환만 바뀌면 geometry_version을, 자세 기준이 바뀌면 calibration_version을 갱신한다.
4. 새 버전에 연결되지 않은 진행 중 탭 주기와 대기 명령을 무효화한다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| CalibrationRequest | 대상 손·손가락, 보정 종류 |
| ObservationBatch[] | 기준 자세·들림 자세의 유효한 관측 |
| DisplayGeometry | 원본 영상→표시 화면 변환·가상 건반 영역 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[CalibrationBundle]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `CalibrationBundle`
- 보존할 업무 필드: `calibration_version, geometry_version, per_finger_templates, transform_ref, key_regions, validity_conditions`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| calibrated | 검증을 통과한 기준 발급 |
| needs_more_samples | 유효한 관측 부족 |
| indistinguishable_pose | 두 자세가 구분되지 않음 |
| unstable_baseline | 기준 자세 불안정 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 손가락별 기준 없이 해당 손가락을 ready로 표시하지 않는다.
- 기준 재수집 시 오래된 템플릿과 섞지 않는다.
- 리사이즈·반전 후 영상과 건반의 동일 점이 같은 위치에 매핑된다.
- 사용자가 보정을 완료하기 전에 요청 도구가 완료를 선언하지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
