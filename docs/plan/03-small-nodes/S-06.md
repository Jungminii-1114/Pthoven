# S-06 · `map_virtual_note` — 가상 건반 매핑과 입력 수용

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

주기 후보 시각의 손끝 위치를 가상 건반에 매핑하고 수용·보류된 가상 음 이벤트를 생성한다.

- 실행 성격: **결정론적**
- 협업 담당: CV·게임
- 범위 제외: 다음 정답 음을 추측하거나 물리 건반 접촉을 확정하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `map_virtual_note(request, context) -> NodeResult[VirtualInputBatch]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| resolve_candidate_coordinates | 후보 시각·좌표 버퍼 | 대응 좌표 또는 unavailable |
| transform_to_key_space | 원본 좌표·기하 | 가상 건반 좌표 |
| resolve_virtual_key | 좌표·건반 경계 정책 | 건반 ID 또는 ambiguous |
| accept_or_withhold_input | 후보·기하·중복 ID | 수용/보류 이벤트 |

## 3. 내부 처리 순서

1. 후보 출력 시각 대신 복귀 후보 시각에 대응하는 좌표를 찾는다.
2. 영상과 건반에 동일한 표시 변환을 사용한다.
3. 경계·영역 밖·버전 불일치일 때 음번호를 null로 둔다.
4. 기대 악보 음을 관측 음의 대체값으로 사용하지 않는다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| TapCandidateBatch | 복귀 후보와 finger·t_ms |
| ObservationBuffer | 시각별 이미지 손끝 좌표 |
| CalibrationBundle | 표시 변환·key_regions·버전 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[VirtualInputBatch]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `VirtualInputBatch`
- 보존할 업무 필드: `events[], source, event_id, t_ms, emitted_ms, virtual_key, midi_note, input_status, quality_flags`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| mapped | 가상 건반에 매핑된 잠정 입력 |
| ambiguous_key | 경계 또는 두 영역에 걸침 |
| coordinate_unavailable | 후보 시각 좌표 없음 |
| version_mismatch | 보정·기하 버전 불일치 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 같은 검지가 다른 위치를 치면 다른 가상 음으로 매핑된다.
- 수용 불가 이벤트의 virtual_key와 midi_note가 모두 null이다.
- 양방향 반전·여백·리사이즈에서 동일 위치가 일관되게 매핑된다.
- 같은 event_id를 두 번 게임에 넣지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
