# S-04 · `assess_observation_quality` — 관측 유효성과 평가 보류 판정

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

영상·손 연결·보정·시간 공백을 평가하여 사용할 구간과 unknown 구간을 분리한다.

- 실행 성격: **결정론적**
- 협업 담당: CV·평가
- 범위 제외: 사용자가 실제로 누르지 않았다는 판단이나 연습 전략 선택은 하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `assess_observation_quality(request, context) -> NodeResult[QualityAssessment]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| check_frame_freshness | 마지막 새 프레임 시각 | 영상 중단·시간 공백 |
| check_observation_validity | 관절·손 연결·버전 | 구간별 사용 가능 상태 |
| segment_unknown_intervals | 시간순 품질 플래그 | 반개구간 [start_ms,end_ms) 목록 |
| summarize_quality | 구간·관측 수·정책 | 분모가 있는 품질 요약 |

## 3. 내부 처리 순서

1. 각 기준의 의미를 분리하고 임의의 접촉 확률로 합치지 않는다.
2. 유효 프레임 비율과 새 프레임 경과 시간을 함께 본다.
3. 관측 불가 구간은 경계 완충 정책을 포함해 명시적으로 기록한다.
4. 즉시 보류가 필요한 상태는 LLM 응답과 독립적으로 알린다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| ObservationBatch[] | 관측 및 누락·처리 오류 |
| CalibrationBundle | 적용 중 버전·유효 조건 |
| QualityPolicy | 구간 길이·기하·시간·관측 기준 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[QualityAssessment]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `QualityAssessment`
- 보존할 업무 필드: `quality_id, quality_state, usable_intervals, unknown_intervals, denominators, reason_codes, policy_version`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| usable_provisional | 가상 동작 평가에 사용할 수 있음 |
| hold_required | 입력 평가 보류 필요 |
| insufficient_observation | 정보 부족 |
| policy_mismatch | 잘못된 정책·버전으로 평가 불가 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 영상이 멈췄는데 직전 프레임 품질만으로 정상 처리하지 않는다.
- 판정 점수를 접촉 확률로 표시하지 않는다.
- unknown 구간이 이벤트 제외와 보고서까지 유지된다.
- 선택 기능을 끈 것만으로 partial을 만들지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
