# S-08 · `build_practice_snapshot` — 연습 지표와 근거 스냅샷 구성

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

정렬·품질·실제 설정·이력을 결합해 코칭이 참조할 불변 스냅샷을 생성한다.

- 실행 성격: **결정론적**
- 협업 담당: 분석·서버
- 범위 제외: 전략 선택·도구 실행·통계값을 LLM이 다시 계산하는 과정은 포함하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `build_practice_snapshot(request, context) -> NodeResult[PracticeSnapshot]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| compute_supported_metrics | 정렬 표본 | 음 일치율·타이밍·표본 수 |
| mark_unavailable_metrics | 미관측 항목·정책 | null와 부족 사유 |
| bind_metric_evidence | 지표·정렬·품질 ID | 값별 근거 참조 |
| freeze_coach_snapshot | 유효 상태·설정 | 불변 snapshot_id와 코치 버전 |

## 3. 내부 처리 순서

1. 지표별 계산 가능 여부와 분모를 보존한다.
2. 눌림·해제 정의가 없는 입력에서 음 길이 지표를 만들지 않는다.
3. 요청된 설정이 아닌 ACK로 확인된 실제 설정을 기록한다.
4. 코치 판단 경계마다 버전을 발급하며 매 프레임 번호와 구분한다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| AlignmentResult | 평가 가능 음·시간 표본 |
| QualityAssessment | 품질·제외 범위 |
| AppliedPracticeConfig | 실제로 확인된 BPM·범위·힌트·버전 |
| AttemptContext | 시도 ID·이전 개입·세션 범위 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[PracticeSnapshot]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `PracticeSnapshot`
- 보존할 업무 필드: `snapshot_id, state_version, metrics, denominators, observation_status, actual_config, evidence_refs`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| snapshot_ready | 사용 가능한 코치 상태 |
| insufficient_metrics | 안전하게 표시할 지표 제한 |
| inconsistent_evidence | 값·출처·설정 불일치 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 접촉 미확인 속성이 보고서 입력까지 유지된다.
- matched/evaluable 비율이 기록된 분모와 일치한다.
- 근거가 없는 음 길이·피로·힘 수치가 추가되지 않는다.
- 과거 스냅샷을 수정하지 않고 새 버전을 만든다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
