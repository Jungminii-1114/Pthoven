# S-05 · `detect_finger_cycle` — 손가락별 들림·복귀 주기 탐지

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

관절 특징의 시간 변화를 사용하여 손가락별 pose_tap_candidate를 중복 없이 만든다.

- 실행 성격: **시계열 상태 머신**
- 협업 담당: CV
- 범위 제외: 가상 음번호 매핑·소리·누르는 힘·접촉 정답 생성은 하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `detect_finger_cycle(request, context) -> NodeResult[TapCandidateBatch]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| extract_pose_features | 관절·손바닥 기준 | 각도·상대 자세·길이 일관성 |
| project_calibrated_pose | 특징·보정 템플릿 | 자세 점수와 잔차 |
| advance_finger_machine | 시각·특징·유효성 | 대기→기준→들림→복귀 전이 |
| emit_cycle_candidate | 완료 주기·출력 시각 | 한 번의 후보와 출력 지연 |

## 3. 내부 처리 순서

1. 손가락별로 상태를 분리한다.
2. 기준 자세를 획득한 뒤 들림·복귀를 순서대로 요구한다.
3. 관측 손실·큰 시간 공백·버전 변경 시 진행 주기를 버린다.
4. 공중 탭도 같은 자세 패턴을 만들 수 있음을 이벤트에 보존한다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| ObservationBatch | 단조 시각·선택 손 관절 |
| CalibrationBundle | 손가락별 자세 템플릿 |
| QualityAssessment | 관측 유효 구간·보류 사유 |
| FingerCycleState | 손가락별 단계·시간·재진입 상태 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[TapCandidateBatch]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `TapCandidateBatch`
- 보존할 업무 필드: `candidates[], updated_cycle_state, withheld_reasons; 후보별 t_ms, emitted_ms, finger, contact_verified=false`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| candidates_emitted | 주기 후보 존재 |
| no_cycle | 정상 관측이지만 후보 없음 |
| withheld | 불안정 관측으로 진행 보류 |
| invalid_clock | 시각 역행·중복 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 정지 손가락에서 후보가 증가하지 않는다.
- 같은 손가락의 새 주기는 다시 탐지된다.
- 가림 이전 주기와 이후 관측을 접촉으로 이어 붙이지 않는다.
- 동일 관측의 공중 탭을 합성 테스트에서 해결했다고 주장하지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
