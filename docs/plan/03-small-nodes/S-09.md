# S-09 · `route_coaching_trigger` — 코칭 호출 조건과 우선순위 결정

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

사용자 요청·구간 종료·품질 악화·재평가 사건을 중복 없이 적절한 코칭 요청으로 변환한다.

- 실행 성격: **결정론적**
- 협업 담당: Agent·서버
- 범위 제외: 모델 호출·전략 문장 생성·장치 제어는 직접 하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `route_coaching_trigger(request, context) -> NodeResult[CoachRequest]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| validate_trigger_scope | 사건·세션 | 요청 범위 검사 |
| deduplicate_trigger | trigger_id·기록 | 중복·재전송 판정 |
| prioritize_quality_and_user_intent | 사건·상태 | 보류·사용자 요청 우선순위 |
| reserve_coaching_budget | 정책·실행 상태 | 한정된 실행 예산 |

## 3. 내부 처리 순서

1. 새 상태가 없는 반복 호출을 억제한다.
2. 품질 보류는 시스템이 즉시 처리하고 코치는 설명·조치를 고른다.
3. 한 세션에 충돌하는 복수 개입 계획이 동시에 실행되지 않게 한다.
4. 세션 종료는 실제 사용자 요청 또는 사전 정의한 종료 사건과 연결한다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| CoachingTrigger | 사건 ID·종류·시도·시각 |
| PracticeSnapshot | 판단 시점의 상태 |
| RunPolicy | 쿨다운·호출 예산·동시 판단 제한 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[CoachRequest]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `CoachRequest`
- 보존할 업무 필드: `request_id, trigger_ref, snapshot_ref, priority, allowed_action_classes, budget_ref`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| coaching_required | 새 코칭 실행 허용 |
| suppressed_duplicate | 중복 사건 |
| wait_for_boundary | 적용·판단 경계 대기 |
| budget_exhausted | 추가 호출 보류 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 같은 실패를 매 프레임 새 요청으로 만들지 않는다.
- 보류 조건인데 LLM이 늦어도 입력 평가는 즉시 멈춘다.
- 사용자가 종료한 세션에 새 연습을 예약하지 않는다.
- 모델 실패 후 무제한 재호출하지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
