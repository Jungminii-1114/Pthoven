# S-14 · `apply_command_and_ack` — 클라이언트 적용과 ACK 생성

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

약속한 경계에서 명령을 검증·원자 적용하고 실제 값이 담긴 ACK를 반환한다.

- 실행 성격: **결정론적**
- 협업 담당: 웹·게임
- 범위 제외: 서버의 개입 성공 확정·교육 효과 판단은 하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `apply_command_and_ack(request, context) -> NodeResult[ApplicationAck]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| check_client_preconditions | 명령·실제 상태 | 만료·epoch·버전·중복 검사 |
| wait_for_apply_boundary | apply_at·게임 단계 | 다음 구간·일시정지 경계 |
| apply_atomic_change_set | 검증된 설정 묶음 | 전체 적용 또는 변경 없음 |
| emit_application_ack | 실제 적용 결과 | 중복 요청에도 동일하게 재전송할 ACK |

## 3. 내부 처리 순서

1. 반쯤 연주한 구간의 템포를 모델 응답 도착 순간 바꾸지 않는다.
2. 모든 설정 검사를 통과한 뒤 묶음 전체를 적용한다.
3. 즉시 품질 보류·수동 변경은 epoch를 갱신해 오래된 명령을 차단한다.
4. 재전송은 다시 적용하지 않고 원래 ACK를 반환한다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| CommandTicket | 설정 변경·전제 조건·적용 시점 |
| ClientControlState | 실제 설정·phase·epoch·적용한 ID 목록 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[ApplicationAck]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `ApplicationAck`
- 보존할 업무 필드: `command_id, result, applied_values, actual_versions, applied_at_ms, reason_code, client_clock_id`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| applied | 실제 값 적용 확인 |
| rejected | 전제 조건 위반으로 변경 없음 |
| duplicate_ack | 이전 적용 결과 재전송 |
| application_unknown | 중단으로 실제 상태 재확인 필요 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 범위만 적용되고 템포는 실패하는 반쪽 설정을 만들지 않는다.
- 만료·재연결 이전 명령을 새 세션에 적용하지 않는다.
- 재전송이 템포를 두 번 변경하지 않는다.
- 사용자 수동 정지가 Agent resume보다 우선한다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
