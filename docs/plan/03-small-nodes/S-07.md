# S-07 · `align_practice_events` — 악보 정렬과 평가 구간 정의

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

가상 입력과 기대 음을 정렬하되 관측 불가 구간을 사용자 오류에서 분리한다.

- 실행 성격: **결정론적**
- 협업 담당: 분석·서버
- 범위 제외: LLM 기반 오류 수 계산·실제 피아노 음향 평가·학습 효과 단정은 하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `align_practice_events(request, context) -> NodeResult[AlignmentResult]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| build_expected_timeline | 곡 범위·BPM | 기대 시각과 인덱스 |
| mask_unobservable_targets | 기대 시각·unknown 구간 | 평가 가능/불가 기대 음 |
| align_virtual_events | 평가 가능 기대 음·입력 | 버전이 있는 정렬 결과 |
| extract_valid_timing_pairs | 정렬·시간 정의 | 표본과 계산 가능성 |

## 3. 내부 처리 순서

1. 입력 출처별로 분석을 분리한다.
2. 시각 기준과 오프셋 추정 규칙을 고정한다.
3. unknown 구간과 겹친 누락은 missed가 아니라 unknown으로 분리한다.
4. 모호한 정렬에는 진단과 보류를 남긴다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| VirtualInputBatch | 수용·보류 이벤트와 출처 |
| ExerciseExcerpt | 기대 음·박자·인덱스·연습 템포 |
| QualityAssessment | 사용 가능한 시각·unknown 구간 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[AlignmentResult]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `AlignmentResult`
- 보존할 업무 필드: `alignment_id, pairs[], matched/wrong/extra/missed/unknown, evaluable_count, excluded_count, timing_samples`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| aligned | 비교 가능한 정렬 확보 |
| partially_evaluable | 일부 기대 음 제외 |
| insufficient_alignment | 정렬 근거 부족 |
| clock_mismatch | 시간 기준을 연결할 수 없음 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 손이 보이지 않은 시간의 무입력을 사용자 실수로 집계하지 않는다.
- 두 후보가 하나의 기대 음을 중복 일치시키지 않는다.
- 제외된 기대 음이 정확도 분모에서 빠지고 제외 수가 표시된다.
- 타이밍 표본이 없으면 오차를 0으로 채우지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
