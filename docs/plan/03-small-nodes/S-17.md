# S-17 · `evaluate_intervention` — 개입 이후 변화 계산

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

허용된 비교 축에서 변화량과 재평가 기준 충족 여부를 계산한다.

- 실행 성격: **결정론적**
- 협업 담당: 분석·Agent
- 범위 제외: 다음 변경 실행·최종 보고서 문장 작성은 하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `evaluate_intervention(request, context) -> NodeResult[InterventionComparison]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| compute_supported_deltas | 유효한 지표 쌍 | 차이·방향·단위 |
| check_predeclared_criteria | 사전 재평가 기준·결과 | 충족/미충족/확인 불가 |
| separate_condition_from_ability | 설정 차이·수치 | 허용되는 해석 범위 |
| emit_review_signal | 비교 결과 | 다음 코칭 사건을 위한 신호 |

## 3. 내부 처리 순서

1. 같은 지표 정의·분모·단위를 사용한다.
2. 힌트 증가나 템포 감소 후의 개선은 그 조건에서의 관측 변화로 설명한다.
3. 원래 목표 복귀 확인은 같은 조건의 별도 시도로 계획한다.
4. Agent가 다음 전략을 선택할 근거를 반환하되 자동으로 템포를 올리지 않는다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| ComparabilityReport | 비교 가능한 지표와 조건 |
| PracticeSnapshot A/B | 수치·표본·근거 |
| InterventionRecord | 실제 적용과 사전 확인 기준 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[InterventionComparison]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `InterventionComparison`
- 보존할 업무 필드: `metric_deltas, criterion_results, comparison_scope, limitations, next_review_signal, evidence_refs`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| comparison_ready | 계산과 조건 설명 확보 |
| insufficient_comparison | 표본 또는 조건 부족 |
| criterion_unavailable | 사전 기준을 판정할 수 없음 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 관측 차이와 인과 효과를 구분한다.
- 이미 끝난 뒤 유리한 성공 기준으로 바꾸지 않는다.
- 실제로 미적용된 개입에 효과를 귀속하지 않는다.
- 사용 가능한 변화가 없으면 개선이라고 출력하지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
