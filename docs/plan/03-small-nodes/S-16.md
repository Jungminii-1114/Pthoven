# S-16 · `compare_attempt_conditions` — 두 시도의 비교 가능성 검사

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

두 시도의 곡·범위·출처·템포·힌트·보정·품질을 대조해 허용되는 비교 축을 정한다.

- 실행 성격: **결정론적**
- 협업 담당: 분석·평가
- 범위 제외: 변화량 계산·능력 향상·전략 성공의 최종 설명은 하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `compare_attempt_conditions(request, context) -> NodeResult[ComparabilityReport]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| match_exercise_scope | 곡·버전·음표 범위 | 대상 동일성 |
| compare_actual_conditions | 출처·BPM·힌트·보정 | 조건 차이 |
| check_metric_support | 지표별 표본·품질 | 비교할 수 있는 축 |
| classify_comparison_scope | 조건·정책 | same_conditions / changed_conditions / not_comparable |

## 3. 내부 처리 순서

1. 가상 카메라 입력과 키보드 기록을 같은 정확도 집계로 섞지 않는다.
2. 템포·힌트가 다르면 조건 차이를 그대로 노출한다.
3. 관측 누락이 큰 경우 해당 축의 비교를 보류한다.
4. 비교 가능한 축이 일부 있어도 제외 축과 이유를 함께 반환한다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| PracticeSnapshot A/B | 두 시도의 실제 설정과 지표 |
| ComparisonPolicy | 비교 축·최소 표본·제외 규칙 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[ComparabilityReport]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `ComparabilityReport`
- 보존할 업무 필드: `comparison_scope, comparable_axes, condition_differences, excluded_axes, caveats, evidence_refs`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| same_conditions | 기록된 핵심 조건 일치 |
| changed_conditions | 조건을 명시하는 제한적 비교 |
| not_comparable | 안전한 비교 축 없음 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 60 BPM과80 BPM을 같은 난이도로 취급하지 않는다.
- 보정 변경·카메라 출처 변경을 누락하지 않는다.
- 한 시도의 null을 0으로 바꿔 차이를 계산하지 않는다.
- 일부 축 제외를 실행 오류와 혼동하지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
