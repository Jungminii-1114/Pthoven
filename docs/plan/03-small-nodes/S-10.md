# S-10 · `build_coach_context` — 모델 컨텍스트와 도구 범위 구성

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

현재 목적에 필요한 스냅샷·최근 개입·허용 도구만 포함한 모델 입력을 구성한다.

- 실행 성격: **결정론적**
- 협업 담당: Agent
- 범위 제외: 추가 조회 전략과 연습 개입의 최종 선택은 하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `build_coach_context(request, context) -> NodeResult[CoachContext]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| select_relevant_history | 요청·이력 | 비교 가능한 최소 이력 |
| expose_allowed_tools | 세션 단계·정책 | 허용 도구 목록 |
| build_evidence_index | 지표·근거 참조 | 모델용 근거 설명과 ID |
| enforce_context_budget | 입력·한도 | 축약·제외 이유와 최종 컨텍스트 |

## 3. 내부 처리 순서

1. 원본 전체 영상이나 모든 프레임을 기본 입력으로 보내지 않는다.
2. 읽기 결과와 실제 적용 이력만 사실로 제공한다.
3. 필요한 추가 정보는 조회 도구로 가져올 수 있게 한다.
4. 근거 데이터의 문자열을 실행 지시나 새 도구 정의로 해석하지 않는다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| CoachRequest | 사건·목표·예산 |
| PracticeSnapshot | 최신 판단 근거 |
| SessionHistory | 관련 시도·적용 이력 |
| ToolRegistry | 읽기·변경 제안 도구 정의 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[CoachContext]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `CoachContext`
- 보존할 업무 필드: `context_id, snapshot_ref, instruction_version, allowed_tool_ids, evidence_refs, history_refs, remaining_budget`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| context_ready | 스키마와 예산을 만족 |
| insufficient_context | 판단 필수 정보 부족 |
| scope_violation | 허용 범위 밖 참조 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 다른 세션의 이벤트·시도가 섞이지 않는다.
- 토큰 축약이 unknown 표시나 실제 설정 버전을 제거하지 않는다.
- 제안된 변경을 실제 적용된 상태로 넣지 않는다.
- 이미지 도구를 비활성화하면 모델 입력에 이미지가 포함되지 않는다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
