# S-18 · `compose_grounded_report` — 근거 기반 보고서 초안 생성

[세부 단계 목록](README.md) · [공통 반환 계약](../05-contracts/common-result.md) · [데이터 모델](../05-contracts/data-models.md)

## 1. 단일 책임과 경계

계산된 사실·불확실성·실제 개입·조건부 변화를 초보자가 이해할 수 있는 보고서로 구성한다.

- 실행 성격: **텍스트 생성**
- 협업 담당: Agent·디자인
- 범위 제외: 자신이 작성한 보고서를 근거 없이 최종 승인하거나 누락 수치를 추정하지 않는다.
- 상위 실행 경로: [Big Node 목록](../02-big-nodes/README.md)에서 관리한다.

## 2. 필요한 함수

진입점은 `compose_grounded_report(request, context) -> NodeResult[ReportDraft]`로 표현한다. 다음 함수는 내부 연산이며 Agent에 자동 공개되는 도구가 아니다.

| 내부 함수 | 입력 | 반환·책임 |
| --- | --- | --- |
| assemble_report_evidence | 허용 범위의 기록 | 보고서용 근거 묶음 |
| render_numeric_facts | 사전 계산 값·단위 | 수치 사실 필드 |
| generate_explanations | 근거·보고서 스키마 | 짧은 문장과 주장별 근거 |
| separate_facts_and_hypotheses | 문장 유형·근거 | 관측·가설·추천 구분 |

## 3. 내부 처리 순서

1. 보고서 문장은 텍스트 모델로 작성하되 숫자는 제공된 값을 사용한다.
2. 제안·적용·불명·실패를 구분한다.
3. 카메라 잠정 입력이라는 측정 범위를 명시한다.
4. 보고서의 그래프·손 위치 이미지는 렌더러로 만들 수 있으며 VLM이 필수는 아니다.

## 4. 입력 계약

| 입력 타입 | 필수 의미 |
| --- | --- |
| ReportRequest | 세션·시도 범위·사용자 목적 |
| EvidenceBundle | 스냅샷·개입·비교·실행 실패 |
| ReportPolicy | 출력 항목·근거 참조·표현 제약 |

세션·시도·시계·버전 참조는 [데이터 모델](../05-contracts/data-models.md)에 따른다. 범위가 맞지 않거나 필수 필드가 없으면 추정값으로 채우지 않는다.

## 5. 출력 계약

반환은 `NodeResult[ReportDraft]`이며 `status`, `data`, `diagnostics`, `outcome` 네 키를 사용한다.

- `data` 타입: `ReportDraft`
- 보존할 업무 필드: `summary, observations[], uncertainties[], actual_actions[], changes[], next_practice[], claims[], evidence_refs`
- `diagnostics`는 위 내부 함수명을 키로 실행·생략·실패와 근거를 기록한다.
- 데이터의 `null`, 빈 목록, unknown은 서로 다른 의미다. [공통 결과 계약](../05-contracts/common-result.md)의 규칙을 따른다.

## 6. 업무 결과와 오류

| outcome | 업무상 의미 |
| --- | --- |
| draft_ready | 검증 가능한 구조화 초안 |
| limited_report | 근거가 제한된 안내 보고서 |
| generation_failed | 모델 오류로 템플릿 대체 필요 |

`outcome`은 `status`와 다른 축이다. 정상적으로 보류·빈 결과·정보 부족을 판단했으면 `status=success`일 수 있다. 실제 필수 처리 실패는 `status=error`로 구분하고, 안전한 일부 산출물이 있을 때만 `partial`을 사용한다. 예외를 잡았다는 이유로 성공으로 바꾸지 않는다.

재시도 가능성은 진단 힌트로 반환하며, 실제 재시도·다음 단계 선택은 하네스가 판단한다. 대기나 비동기 실행을 실행 오류와 혼동하지 않는다.

## 7. 검증 사례

- 근거 없는 피로·근력·손가락 독립성 진단을 넣지 않는다.
- 미적용 명령을 수행했다고 쓰지 않는다.
- 표본이 없을 때 성적·향상을 꾸며 넣지 않는다.
- 사실과 추천의 문장 유형을 구분한다.

## 8. 설계 검토 항목

- 필드 타입·단위·버전과 유효 구간을 팀 계약에 맞춰 고정한다.
- 실행 한도·정책값은 [결정 항목](../07-decision-points.md)의 측정 절차로 선택한다.
- 근거·실행 상태·보류 사유가 다음 단계에서 소실되지 않는지 확인한다.

이 문서는 구현 책임과 검증 기준을 정의하며 현재 코드·완료율·구현 진척을 기록하지 않는다.
