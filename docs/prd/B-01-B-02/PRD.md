## 1. 해결할 문제와 성공 경험

사용자는 위에서 책상과 손을 촬영하는 RGB 카메라와 노트북 화면만으로 가상 피아노를 연주한다. 필요한 것은 화면에 손 관절을 그리는 기능을 넘어, 선택 장치·개인 보정·좌표·시간이 일관된 상태에서 손가락의 들림→복귀를 가상 음 입력으로 변환하는 기능이다.

성공 경험은 다음과 같다.

1. 사용자가 iPhone 연속성 카메라 또는 노트북 웹캠을 직접 선택한다.
2. 화면 방향과 가상 건반 배치를 확인한다.
3. 한 손과 사용할 손가락을 선택하고 기준·들림 자세를 저장한다.
4. 유효한 보정이 있는 손가락으로 짧은 검증 동작을 한다.
5. 후보 시각의 손끝이 위치한 가상 건반이 반응하고 해당 음의 입력 사건이 생성된다.
6. 가림·카메라 정지·경계 위치는 사용자 실수로 확정되지 않고 보류 사유로 표시된다.

**산출물의 의미:** RGB 관측 기반 `pose_tap_candidate`와 `accepted_provisional` 가상 입력이다. 실제 책상 접촉·누르는 힘·피아노 음향을 측정했다는 뜻이 아니다. 공중에서 같은 궤적을 만들면 구분하지 못할 수 있다.

## 2. 개발 범위

### 2.1 두 Big Node와 Small Node 대응

| Big Node | 포함 Small Node | 개발 책임 | 완료 시 전달할 것 |
|---|---|---|---|
| B-01 세션 준비와 보정 | S-01·S-02·S-03·S-04 | 장치·세션·시계·표시 기하 준비, 기준 수집, 손가락별 보정, 준비 여부 판정 | `SessionContext`, `CalibrationBundle`, `QualityAssessment` |
| B-02 실시간 관측과 가상 연주 입력 | S-02·S-04·S-05·S-06 | 새 프레임 관측, 품질 게이트, 손가락별 주기, 가상 건반 매핑, 사건 발행 | `VirtualInputBatch`, 품질 구간, 재생 가능한 관측·진단 |

S-02와 S-04는 두 Big Node가 공유하는 단일 구현이다. 보정 화면과 연주 화면에 서로 다른 관측·품질 알고리즘을 만들지 않는다. Small Node는 다른 Small Node를 직접 호출하지 않고 Big Node 실행기가 순서를 관리한다.

### 2.2 우선순위

| 수준 | 기능 |
|---|---|
| P0 필수 | 한 카메라·한 선택 손, 다섯 손가락의 독립 보정/상태 구조, 활성 손가락 부분집합, 가상 흰 건반, 좌우·상하 반전, Python 판정, 보류·복구, 로그·리플레이, B-03 전달 계약 |
| P1 후속 | 검은 건반·다성 입력 체험 확대, 선택적 브라우저 추론 어댑터, 안전성이 검증된 짧은 품질 유예, 선택적 영상 기록, 조건을 만족하는 보정 재사용 |
| 실험 분기 | Depth Anything, 손등 표면 흐름, 다른 손 추적 모델, 학습형 주기 분류기. 각 분기는 공통 계약과 독립 평가를 통과해야 한다. |

P0에서도 엄지·검지·중지·약지·소지의 경로를 각각 구현·합성 검증한다. 실제 사용자에서 보정 가능한 손가락만 활성화한다. 약지까지 모두 같은 정확도가 나온다고 가정하거나, 검지만 통과한 상태를 다섯 손가락 현장 검증 완료로 기록하지 않는다.

### 2.3 범위 밖

- 아이패드·GarageBand·실물 피아노 인식·ArUco 정합, 마이크·타격음·물리 MIDI 입력.
- 책상 기준 mm 높이, 물리 접촉·압력·velocity·누름 지속시간의 확정.
- 곡 다운로드·Mutopia/nASAP 전처리기 전체 개발. B-01은 준비된 곡 참조와 지원 음역을 검증한다.
- 정답 악보와의 score following·오음 판정·연주 점수 산출: B-03 책임.
- LLM 도구 선택·연습 전략·최종 보고서·Agent 명령 실행기: B-04 이후 책임.

MIDI는 기대 악보의 음높이·리듬 표현이다. 실제 사용자 입력의 기본 출처는 `camera_pose`다. 개발용 키보드·포인터·리플레이는 별도 출처로 기록한다.

## 5. 사용자 흐름과 화면 요구사항

### 5.1 세션 시작

`장치 선택 → 연결 → 새 영상 확인 → 추적 모델 준비 → 손 선택 → 건반 배치/방향 확인 → 기준 수집 → 손가락별 들림 수집 → 입력 점검 → 연습 진입`

- 카메라 권한 허용 전 장치명이 비어 있어도 오류로 단정하지 않는다. 권한 요청 후 목록을 갱신한다.
- 사용 가능한 장치명·현재 활성 장치명을 표시한다. 운영체제가 제공하지 않는 iPhone을 웹에서 발견했다고 표시하지 않는다.
- ‘영상 수신 중’과 ‘손 추적 준비 완료’를 따로 표시한다. 모델 실패 시 프리뷰·장치 선택·도움말은 유지한다.
- 좌우/상하 반전 기본값은 모두 꺼짐으로 제안한다. 자동 변경하지 않고 사용자 선택을 표시한다.
- 브라우저 자동 오디오 정책에 맞춰 ‘연습 시작’ 사용자 동작에서 오디오를 준비한다. 음 재생 실패가 타건 사건을 삭제하지는 않는다.

### 5.2 보정

- 사용할 손가락의 기본 부분집합은 검지 한 개다. 사용자가 다섯 손가락 중 추가 선택한다.
- 기준 자세는 손을 자연스럽게 둔 상태, 들림은 대상 손가락을 자연스럽게 들고 안정시킨 상태다. 비정상적으로 높이 들거나 손 전체를 바꾸도록 유도하지 않는다.
- 준비 시간·현재 유효 프레임·남은 수집 시간·누락·실패 사유를 보여준다.
- 기준 자세 재저장은 해당 기준을 공유하는 이전 손가락 템플릿을 무효화한다. 사용자가 그 영향을 알 수 있어야 한다.
- 들림 보정 하나가 실패해도 다른 유효한 손가락 보정은 보존한다. 실패 손가락은 비활성 상태로 남긴다.
- 약지 움직임이 작으면 제한 안에서 수집 시간을 늘릴 수 있다. 길이 왜곡·불가분 자세를 프레임 수만 늘려 통과시키지는 않는다.
- 성공한 손가락은 ‘보정 완료’, 기준 자세 재확인까지 끝나면 ‘입력 준비’로 표시한다.

### 5.3 입력 점검과 실행

- 점검 모드는 연습 점수에 반영하지 않는다. 선택 손가락·주기 단계·후보 횟수·최근 보류 사유·현재 가상 음을 표시한다.
- 일반 화면에서는 짧은 상태 문구만 제공하고 상세 수치·그래프는 진단 패널에서 제공한다.
- 민트 TIP·노랑 관절 그래프는 무차원 자세 점수이며 실제 높이·확률이 아님을 표기한다. 유효하지 않은 구간은 선을 끊는다.
- 좌측 프리뷰는 고정 영역, 우측 설정·진단은 독립 스크롤로 구성한다. 상태 문구 길이나 프레임 수 변화로 프리뷰 높이가 바뀌지 않아야 한다.
- 상세 UI 갱신은 최대 5Hz 제안값을 사용하되, 입력·보류·카메라 오류는 즉시 반영한다. UI 갱신 주기가 추론 주기를 제한해서는 안 된다.

## 6. B-01 기능 요구사항

| ID | 기능과 필수 동작 | 실패·수용 조건 |
|---|---|---|
| B01-01 | 선택 장치·입력 출처·연습곡·손·활성 손가락을 검증한다. | 존재하지 않는 장치/곡/손가락으로 준비 완료를 반환하지 않는다. |
| B01-02 | `session_id`, `clock_id`, 정책·모델 식별자, `command_epoch`를 만든다. | 재연결 이전의 프레임·작업 결과는 새 세대에 적용하지 않는다. |
| B01-03 | 프리뷰 연결·새 프레임 수신·추론 준비·선택 손 관측을 별도 상태로 관리한다. | 한 상태의 성공으로 다른 상태의 성공을 추정하지 않는다. |
| B01-04 | 화면 크기·영상 크기·object-fit·반전·건반 위치를 기하 버전으로 발급한다. | 변환이 비가역/잘못된 경우 건반 매핑을 비활성화한다. |
| B01-05 | 기준/들림을 새 프레임으로 수집하고 품질 탈락 사유를 보존한다. | 오래된 프레임 복제·타임스탬프 재사용으로 최소 표본 수를 채우지 않는다. |
| B01-06 | 손가락별 TIP·관절 특징을 따로 보정하고 안정적인 특징만 선택한다. | 한 그룹이 구분되지 않으면 다른 그룹만으로 성공 처리하지 않는다. |
| B01-07 | 길이의 공통 배율과 구간별 왜곡을 분리해 진단한다. | 손가락을 펴며 끝점 거리가 달라진 것을 곧바로 뼈 길이 변화로 판정하지 않는다. |
| B01-08 | 관측 수·잡음·자세 분리·길이 통과 비율을 검사한다. | 실패 기준과 실제 값을 반환한다. 자동 임계값 완화는 금지한다. |
| B01-09 | 보정 결과를 원자적으로 발급하고 버전·수집 조건을 묶는다. | 취소되거나 오래된 비동기 결과가 유효 템플릿을 덮어쓰지 않는다. |
| B01-10 | 입력 점검을 통과한 활성 부분집합으로 B-02를 시작한다. | 보정이 없는 손가락은 추적되더라도 입력 사건을 내지 않는다. |
| B01-11 | 취소·재시도·손 변경·장치 변경·화면 방향 변경의 무효화 범위를 적용한다. | [변경 표](TECHNICAL_SPEC.md#3-버전과-무효화)를 만족한다. |
| B01-12 | 재보정 요청을 받아 입력 평가를 중지하고 보정 화면 진입 사실을 반환한다. | `request_recalibration` 수신만으로 `calibrated`를 반환하지 않는다. |

## 7. B-02 기능 요구사항

| ID | 기능과 필수 동작 | 실패·수용 조건 |

| B02-05 | 기준→들림→복귀 순서를 손가락별로 추적한다. | 정지·한 프레임 튐·들림 유지·복구 자체는 반복 타건이 아니다. |
| B02-06 | 복귀 후보 시각·그 시점의 좌표 참조·출력 시각·진단을 보존한다. | 출력 시점 좌표로 과거 후보의 음을 바꾸지 않는다. |
| B02-07 | 가상 건반의 실제 영역으로 좌표를 매핑한다. | 경계·영역 밖·좌표 없음은 `midi_note=null`이다. |
| B02-08 | 동일 후보를 한 번만 사건으로 발행하고 음 재생도 중복 억제한다. | 재전송·순서 변경·브라우저 재연결로 사건 수가 늘지 않는다. |
| B02-09 | 영상/관측 중단을 watchdog으로 감지한다. | 새 프레임이 없어도 마지막 ‘정상’ 상태가 영구 유지되지 않는다. |
| B02-10 | unknown 구간·사유·평가 가능한 분모를 B-03에 전달한다. | 관측 중단 중 미입력을 missed로 확정하는 데이터는 만들지 않는다. |
| B02-11 | 활성 손가락의 동시 후보를 독립 보존한다. | 동시 후보를 하나로 합치거나 손가락 이름만으로 음을 정하지 않는다. |
| B02-12 | 기록과 리플레이에 버전·원본 출처·실패를 보존한다. | 리플레이를 실시간 연주로 표시하거나 실패 프레임을 제거하지 않는다. |

## 8. 경계와 연결 계약

### 8.1 Python과 웹

기본 경로는 **브라우저의 RGB 프레임 획득 → 로컬 Python CV worker → Python 품질/보정/주기/음 매핑 → 브라우저 표시**다. Python을 기본 구현 언어로 사용한다. 웹은 장치 권한·프레임 획득·운반·표시·오디오·다운로드 및 브라우저 시각 확정만 담당한다.

브라우저 MediaPipe 추론은 P1 대체 어댑터다. 사용한다면 추론 위치·모델/SDK 버전을 기록하고, 두 추론기를 동시에 실행하거나 Python 실패를 알리지 않고 대체하지 않는다. 판정·보정·매핑 수학은 양쪽 언어에 중복 구현하지 않는다.

### 8.2 B-03

- 전달: 수용/보류된 가상 음 사건, `t_ms`, 출처·시계·버전, 품질 구간, 유효 분모, 근거 참조.
- B-03이 기대 악보를 소유한다. B-02의 매핑 함수는 `expected_note`를 입력받지 않는다.
- P0는 onset만 제공한다. note-off·실제 duration·velocity를 측정값으로 제공하지 않는다.
- 보류 사건과 unknown 구간을 보존하며 실제 연주 실수 여부는 분석 담당이 별도로 결정한다.

### 8.3 Agent/명령 계층

B-01·B-02 내부 함수는 Agent Tool로 자동 등록하지 않는다. Agent는 이미 정의된 조회·재보정 요청 도구를 통해 구조화 상태를 받는다. 여기서는 `ObservationQualityChanged`, `CalibrationRequired`, `InputPipelineReady`, `StreamStopped` 사건과 버전 조회 인터페이스를 제공한다. Agent 명령의 승인·stage·ACK 전체 구현은 범위 밖이다.

## 11. 팀 인수 체크리스트

- [ ] 다섯 손가락 합성 시험과 실제 사용자 시험 결과를 구분했다.
- [ ] B-03 소비자가 unknown을 실수로 처리하지 않는 계약 시험을 통과했다.
- [ ] 모델·환경·정책 고정 방법, 실행·기록·재생 방법을 제공했다.
- [ ] 원본 영상·랜드마크·라벨·개발 fixture의 보관 범위와 접근 범위를 명시했다.
- [ ] 실제 접촉·깊이·압력·능력 향상을 검증했다는 표현이 없다.
