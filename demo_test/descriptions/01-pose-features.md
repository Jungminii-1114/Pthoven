# 01 · 손 기준 좌표계와 관절 특징

[목차](README.md) · [코드](../models/tap-detector.mjs)

## 목적과 책임

카메라에 대한 손의 이동·회전·크기 차이를 줄이고 개별 손가락의 자세 변화를 비교한다. `features()`는 특징 계산만 담당하며 보정·타건 판정·접촉 판단은 수행하지 않는다.

## 입력

21개 손 관절의 일관된 3D 좌표를 순서대로 전달한다. 각 점은 `[x,y,z]` 또는 `{x,y,z}`다. 실촬영에서는 MediaPipe의 **world landmarks**가 이 입력에 해당한다.

- 손목 0
- 엄지 1~4 / 검지 5~8 / 중지 9~12 / 약지 13~16 / 소지 17~20
- 정규화된 영상 x/y와 다른 단위의 z를 임의로 섞지 않는다.
- 같은 손을 프레임 사이에 유지해야 한다. 손 선택·ID 연결은 상위 수집기의 책임이다.

## 좌표계 계산

손바닥 폭을 `s = ||p5-p17||`로 두고 다음 축을 구성한다.

1. `x̂ = normalize(p5-p17)`
2. `v = p9-p0`
3. `ŷ = normalize(v-x̂(v·x̂))`
4. `ẑ = normalize(x̂×ŷ)`

각 관절을 손목 기준으로 옮긴 뒤 축에 투영하고 손바닥 폭으로 나눈다.

```text
qᵢ = [(pᵢ-p₀)·x̂, (pᵢ-p₀)·ŷ, (pᵢ-p₀)·ẑ] / s
```

이상적인 입력에서 전역 평행이동·회전·양의 균일 배율에 불변인 표현이다. 좌표가 잡음·가림으로 틀어지면 실제 관측에서는 완전한 불변성을 보장하지 않는다.

## 손가락별 특징

손가락의 점을 `a,b,c,d`라고 할 때 일반 손가락은 MCP/PIP/DIP/TIP 순서다. 엄지는 1/2/3/4번 관절을 같은 계산 경로에 넣으며 해부학적 관절 명칭은 다르다.

| 특징 벡터 위치 | 계산 | 의미 |
| --- | --- | --- |
| 0 | `d.z-a.z` | 손 기준 축에서 손끝의 상대 위치 |
| 1 | `angle(q0,a,b)/π` | 손목·뿌리·다음 관절의 각도 특징 |
| 2 | `angle(a,b,c)/π` | 중간 관절의 굽힘 특징 |
| 3 | `angle(b,c,d)/π` | 끝 관절의 굽힘 특징 |
| 4 | `||d-a||` | 뿌리에서 손끝까지 거리 |

추가로 `||b-a||`, `||c-b||`, `||d-c||`를 저장해 프레임별 길이 이상치를 검사한다.

`angle(A,B,C)`는 `acos(((A-B)·(C-B))/(||A-B||||C-B||))`로 계산하며, 부동소수 오차를 막기 위해 acos 입력을 -1~1로 제한한다.

## 출력과 오류

```javascript
const result = features(worldLandmarks);
// result.index = {vector: [다섯 특징], lengths: [세 마디 길이]}
```

21개 점이 아니거나 유한하지 않은 값, 폭·축·관절 벡터가 퇴화하면 예외를 발생시킨다. 타건 검출기는 이 예외를 받아 해당 관측을 보류한다.

## 검증과 한계

`tests/test_tap.mjs`는 90도 각도, 좌표 변환 불변성, 퇴화 입력, 손 전체 수직 이동의 제거를 검사한다. 해석적 관절을 사용한 수학·로직 검증이다.

손 전체가 같은 자세로 위아래로 움직이면 손 기준 특징은 같아진다. 따라서 이 표현은 **책상까지의 절대 높이를 잃는다**. world 좌표도 모델이 추정한 손 자세이며, 책상 기준의 정확한 mm 높이나 접촉을 뜻하지 않는다. 같은 특징을 만드는 공중 동작은 [상태 머신](03-finger-state-machine.md)만으로 구분할 수 없다.

입력 모델의 좌표 정의는 [MediaPipe 공식 문서](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker)를 참고한다.
