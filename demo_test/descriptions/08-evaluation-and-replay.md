# 08 · 이벤트 평가·불명 구간·재생·집계

[목차](README.md) · [기초 평가](../models/tap-detector.mjs) · [시행 평가](../models/depth-detector.mjs)

## 평가 단위

정답 건반의 음정이 아니라 **손가락별 입력 이벤트와 시각**을 평가한다. 악보와의 음정·템포·길이 분석은 후속 시스템의 책임이다.

프레임마다 정지 상태가 많으므로 프레임 정확도만 쓰면 좋은 수치가 나올 수 있다. 실제 입력 관점의 이벤트 precision/recall/F1, 오입력, 타이밍, 관측률, 지연을 함께 본다.

## 독립 정답

| 값 | 의미 | F1 |
| --- | --- | --- |
| `truth: null` | 미라벨·확인 불가 | 계산하지 않음 |
| `truth: []` | 확인된 무타건 | 오입력 평가 가능 |
| `truth: [{finger,t_ms}, ...]` | 검수한 실제 이벤트 | 정렬 후 계산 |

v2 시행은 `annotation_confirmed:true`도 필요하다. 이는 검수자의 확인 필드이며 시스템이 접촉을 자동 검증했다는 뜻은 아니다. 예측·연습 지시·시작 신호를 정답으로 복사하지 않는다.

상단 영상에서 접촉을 구분할 수 없으면 불명으로 남긴다. 검수 가능한 동작 후보만 라벨링했다면 실제 물리 접촉 정확도라고 부르지 않는다. 접촉 정확도 평가에는 독립 참고 영상·센서 등의 근거와 시간 정렬이 필요하며 운영 입력에 이를 추가해야 한다는 의미는 아니다.

## 손가락별 일대일 정렬

`evaluateEvents()`는 각 손가락의 예측·정답을 시각순으로 정렬한 뒤 동적 계획법으로 대응시킨다.

1. 허용 오차 이내인 대응만 후보로 둔다. 기본 허용 오차는 100ms다.
2. 대응 수를 최대화한다.
3. 같은 대응 수에서는 시각 오차 합을 최소화한다.
4. 하나의 정답·예측은 한 번만 매칭한다.

```text
TP = 매칭된 이벤트 수
FP = 매칭되지 않은 예측 수
FN = 매칭되지 않은 정답 수
precision = TP/(TP+FP)
recall = TP/(TP+FN)
F1 = 2TP/(2TP+FP+FN)
timing_MAE = mean(|예측 시각-정답 시각|)  # 매칭된 쌍
```

분모가 0인 지표는 null이다. 정지 시행에 예측도 정답도 없으면 F1=1로 만들어 넣지 않는다. FP/분과 관측률로 해석한다.

## 불명 구간 처리

`evaluateTrial()`은 `unknown_intervals:[[start,end],...]`를 시행 범위로 잘라 겹치는 구간을 합친다. 그 안의 예측과 정답을 평가에서 제외하고, 알려진 시간만 FP/분의 분모로 사용한다.

**모델이 손을 놓친 구간**과 **정답 자체가 불명인 구간**은 다르다. 독립 영상으로 실제 타건이 확인되었다면 추적 손실은 FN이 될 수 있다. 추적에 실패했다는 이유만으로 평가 구간을 지우면 성능이 부풀려진다.

## 보조 지표

| 지표 | 현재 계산 |
| --- | --- |
| FP/분 | `FP / (불명 제외 시간 / 60000)` |
| 관측률 | 직전 샘플에서 보정된 손가락 중 하나 이상이 valid이고 허용 공백 이내인 시간 / 전체 시행 시간 |
| 출력 지연 평균 | 포함된 예측의 `emitted_ms-t_ms` 평균 |
| excluded_predictions | 시행 밖·불명 구간·비유한 시각 등으로 제외한 예측 수 |

관측률은 전체 손가락 각각의 정확도나 독립 접촉 라벨의 coverage가 아니다. 평균 출력 지연도 실제 접촉 지연이 아니다. 해석적 시각을 넣은 합성 실험의 지연을 실기기 지연으로 보고하지 않는다.

## 오프라인 실행 도구

| CLI | 입력 | 하는 일 |
| --- | --- | --- |
| `check_tap.mjs` | 없으면 합성 관절 / `--capture`로 v1 | 관절 기준선의 재생·stress 검사·이벤트 평가 |
| `analyze_skin.py` | v1 패치 기록 | 피부 특징만 추출 |
| `replay_depth.mjs` | v2 관절·깊이 특징 기록 | 저장한 보정·옵션으로 네 경로의 판정을 재실행 |
| `evaluate_depth.mjs` | 하나 이상의 v2 파일 | 저장된 예측의 평가와 조건별 집계 |

```bash
node scripts/check_tap.mjs --capture data/tap-v1.json --output outputs/tap-replay.json
node scripts/replay_depth.mjs data/depth-v2.json > outputs/depth-replay.json
node scripts/evaluate_depth.mjs data/p01.json data/p02.json > outputs/cohorts.json
```

v1의 기초 evaluateEvents는 truth 배열만 판단한다. v2의 annotation_confirmed·불명 마스크를 적용하려면 evaluateTrial 경로를 사용한다. 두 계약을 혼동하지 않는다.

## 재생의 범위

`replay_depth.mjs`는 모델 추론을 다시 실행하지 않는다. 저장된 world landmarks와 깊이 특징에서 점수·상태 머신을 재계산한다. 재생된 signals로 관측률도 다시 계산하므로, 원본 판정의 valid 플래그를 새 결과로 재사용하지 않는다.

관절 전체 경로는 기록된 emitted_ms가 있으면 사용한다. 깊이 경로의 emitted_ms는 `t_ms+roundtrip_ms`에서 재구성한 근사값이다. 출력에 latency_source를 명시한다. 재생 출력 지연을 새 카메라·새 모델 실행의 측정값으로 취급하지 않는다. 원본 evidence_type은 original_source로 유지한다.

## 조건별 집계와 데이터 분할

`evaluate_depth.mjs`는 라벨이 확인된 시행만 집계한다.

- dev/test를 분리한다.
- 각 split의 시나리오별, 설정별 집계를 별도로 제공한다.
- options·model revision·input_size·request_interval_ms로 config_id를 만든다. **이 ID는 전체 실험 조건의 완전한 해시가 아니다.** 사용자·보정·조명·카메라 위치·의존성 버전은 추가 기록한다.
- 개발/평가에 같은 person_id가 있으면 목록을 출력한다. 사용자 중복이 없다는 사실만으로 세션 독립성·데이터 누수가 모두 검증되는 것은 아니다.
- 같은 파일이나 시행을 중복 입력하면 중복 집계될 수 있으므로 입력 목록을 관리한다.

최종 판단은 새 사용자·고정 조건에서 F1 개선, 정지·공중 탭 FP 감소, 충분한 관측률, 허용 가능한 지연을 함께 확인한다. 템포·조명·사용자·입력 해상도가 다른 결과를 하나의 정확도로만 요약하지 않는다.

## 검증 범위

테스트는 미라벨과 무타건의 구분, 정답 1개에 대한 예측 중복, 손가락별 정렬, 불명 구간 제외, 재생 출처 유지 등을 검사한다. 이것은 평가 로직의 검증이며 실제 타건 인식률을 증명하지 않는다.
