# Pthoven Python 타건 후보 판정

길이 검사, TIP 특징·궤적, 관절각, 개인 보정, 손가락별 상태 머신, JSON 재생을 Python으로 구현한 실험 모듈입니다. 웹·JavaScript·Java 없이 랜드마크 JSON만으로 실행할 수 있습니다. RGB 모델이 추정한 좌표를 사용하므로 실제 접촉·밀리미터 높이를 측정하지 않습니다.

## 실행

저장소 루트에서 Python 3.10 이상으로 설치합니다.

```bash
python -m pip install -e demo_test/python_tap
python -m pthoven_tap demo --output outputs/python-tap-demo.json
```

`demo`는 수학적으로 만든 손으로 로직을 확인합니다. 카메라·사람 실험 정확도가 아닙니다. 추가 의존성은 NumPy이며 카메라나 웹을 실행하지 않습니다.

이미 NumPy가 설치된 Python이면 패키지를 설치하지 않고도 `python demo_test/python_tap/run.py demo --output outputs/python-tap-demo.json`으로 실행할 수 있습니다.

이전 웹에서 저장한 `pthoven-calibration-diagnostics.json`도 Python에서 다시 보정할 수 있습니다.

```bash
python -m pthoven_tap calibrate --input pthoven-calibration-diagnostics.json --output outputs/calibration-python.json
python -m pthoven_tap replay --input pthoven-python-tap-capture.json --model outputs/calibration-python.json --output outputs/replayed-python.json
python -m unittest discover -s demo_test/python_tap/tests -v
```

`calibrate`는 진단 JSON의 마지막 기준·들림 쌍을 사용합니다. 품질 조건 미달 시 `ok=false`와 사유를 파일에 저장하고 종료 코드 2를 반환합니다. 이전 JavaScript 모델을 그대로 Python 모델로 사용하지 않습니다. 원본 기준·들림 랜드마크로 다시 보정합니다. `replay`는 단일 frames 배열 또는 첫 번째 trial을 분석하며, 정답이 없으면 정확도나 F1을 만들지 않습니다.

웹의 **최근 10초 타건 진단 저장** 또는 기존 **JSON 내려받기**로 얻은 기록에는 보정 모델이 함께 들어 있습니다. 이때는 별도 `--model` 없이 그대로 재생합니다. 여러 시행이 있으면 `--trial-index 1`처럼 선택합니다(0부터 시작).

```bash
python -m pthoven_tap replay --input ~/Downloads/pthoven-live-tap-diagnostics.json --output outputs/live-replayed.json
```

최근 구간 저장은 실제 처리된 원본 좌표와 Python 응답을 최대 10초/1,200프레임까지만 메모리에 보존합니다. 모델·세션 변경 시 비웁니다. 영상은 포함하지 않습니다. 구간 시작 이전의 상태는 없으므로, 재생 첫 동작은 원래 실시간 결과와 다를 수 있습니다. 완전한 시행 비교는 기준 자세부터 10초 기록 기능을 사용합니다.

## 1. 길이 검사 재설계

MCP→TIP 직선거리는 손가락을 굽히면 달라집니다. 이 값에 뼈 길이 불변 제약을 걸지 않습니다. 인접한 세 구간의 원래 3D 길이 `l = [MCP–PIP, PIP–DIP, DIP–TIP]`를 검사합니다. 엄지는 해당 4개 랜드마크의 인접 구간을 사용합니다.

이전 방식은 매 프레임 손바닥 폭으로 나눈 길이와 기준 길이를 직접 비교했습니다. 새 방식은 아래를 분리합니다.

```text
ratios = live_lengths / reference_lengths
common_scale = median(ratios)
shape_error = max(abs(ratios / common_scale - 1))
palm_scale = live_palm_width / reference_palm_width
relative_scale = common_scale / palm_scale
```

세 구간이 함께 34.8% 변하면 `common_scale=1.348`, `shape_error≈0`입니다. 한 구간만 34.8% 변하면 국소 왜곡이 남습니다. 공통 배율은 손바닥 대비 0.5~1.8 범위, 국소 왜곡은 최대 30%를 기본 조건으로 사용합니다. 극단적인 상대 스케일·구간 붕괴는 계속 보류합니다. 이 수치는 초기 실험 정책이며 사람 데이터에서 최적화된 값이 아닙니다.

공통 배율을 허용하는 것은 실제 뼈 길이가 변한다는 뜻이 아닙니다. 모델 추정·정규화의 공통 변화와 국소적인 형태 붕괴를 구분하는 방법입니다. 이전 방식의 오차도 진단에 함께 남겨 비교합니다. 원본 프레임에서 왜곡이 국소적인지 확인하기 전에는 특정 실패가 해결됐다고 단정할 수 없습니다.

보정 진단은 동작 신호 통과율과 길이 통과율을 분리하며, 구간별 오차와 95백분위도 표시합니다. 중앙 오차가 30% 미만이어도 일부 프레임은 기준을 초과할 수 있습니다. 동작은 분리되지만 길이 때문에 실패하면 `lift_geometry_unstable`로 표시합니다. 이 진단 추가로 허용 범위를 완화하지 않습니다.

## 2. TIP 궤적과 관절각 결합

- TIP: 손가락 뿌리 기준 손바닥 로컬 3D 위치. 영상 좌표가 있으면 손바닥 로컬 2D TIP 위치도 사용합니다. 손 전체 평행 이동·회전을 최대한 분리합니다.
- 관절: 뿌리·중간·끝 관절의 3점 각도입니다. 뿌리 각도는 손목–뿌리–다음 관절의 기하학적 대리 특징이며, 분리된 해부학적 MCP 굴곡각의 정밀 측정값은 아닙니다.
- 두 그룹에서 각각 변동 대비 자세 차이가 충분한 특징을 선택하고 역분산 가중 점수를 만듭니다. 한 그룹의 큰 좌표값이 다른 그룹을 압도하지 않도록 두 점수를 따로 계산합니다.
- TIP 점수와 관절 점수가 **모두 들림**, **모두 복귀**해야 후보가 됩니다. TIP만 옆으로 끌거나 관절 신호만 변하는 경우를 따로 검사합니다.
- TIP 점수 변화 속도, 선택된 TIP 공간의 이동 경로, 최대 들림·복귀를 시간 순서로 확인합니다. 속도·경로 단위는 정규화된 모델 공간이며 실제 m/s·mm가 아닙니다.

기본 정책: 들림 0.55, 복귀 0.20, 들림 최소 60ms, 복귀 유지 40ms, 재입력 간격 100ms, 관측 공백 최대 200ms입니다. 공백·가림 후에는 새 기준→들림→복귀를 요구합니다. 미래 프레임을 미리 사용하지 않습니다.

이동폭은 관측한 기준 구간의 TIP 최저점부터 들림 최고점까지 계산합니다. 들림 직전 복귀 경계에 가까운 점으로 기준을 덮으면 실제 이동폭을 과소평가할 수 있습니다. 이 수정은 들림·경로·최소 시간 조건을 낮추지 않습니다.

## 타건 횟수가 늘지 않을 때 확인

보정은 두 정지 자세의 구분을 확인합니다. 실제 왕복 동작의 성공을 보장하지 않습니다. `signals[finger].decision`에 Python의 판정 사유·임계값·동작 중단 누적 횟수·마지막 중단 시각을 남깁니다.

| 코드 | 의미 |
|---|---|
| `waiting_for_rest` | TIP·관절 모두 복귀 기준 이하가 되어야 시작 가능 |
| `waiting_for_lift` + `angles_below_lift` 등 | 한쪽 신호가 들림 기준에 도달하지 않음 |
| `waiting_for_return` | 한쪽 신호가 복귀 기준까지 돌아오지 않음 |
| `local_bone_distortion` / `tracking_gap` | 관측 품질 탈락으로 진행 중인 동작 초기화 |
| `lift_too_short` | 관측된 들림 구간이 60ms보다 짧음 |
| `return_unstable` / `settling` | 복귀 상태를 유지하는 중이거나 다시 이탈 |
| `insufficient_tip_motion` | TIP 이동폭·누적 경로·복귀 속도 조건 미달 |
| `candidate_emitted` | 모든 조건을 만족한 타건 후보 |

`diagnostic_summary`는 손가락별 상태 프레임 수, 보류 조건, 중단 횟수와 후보 수를 집계합니다. 프레임별 대기 횟수는 놓친 실제 타건 횟수가 아니며, 조건은 겹칠 수 있습니다. 임계값을 바꾸기 전에 동일 원본에서 어떤 조건이 원인인지 확인하는 용도입니다. 이 진단 개선만으로 실제 인식률이 높아졌다고 주장하지 않습니다.

## 입력 좌표 검사와 상대 기준 실험

영상 정규화 좌표 중 손목·다른 손가락이 화면 밖에 있다는 이유로 전체 관측을 폐기하지 않습니다. 좌표를 0~1로 강제로 자르지도 않습니다. 평가 손가락의 네 관절과 MCP 기준점(5·9·17)이 벗어났을 때 해당 손가락을 보류합니다. `image_visibility`에 화면 밖 좌표와 평가에 필요한 좌표의 이탈을 나눠 남깁니다. 화면 밖 손목은 모델 추정값이므로 손바닥까지 촬영하는 것이 유리합니다.

`mode="fixed"`는 기존 고정 기준 방식입니다. `mode="local_baseline"`은 다음 가설을 검증하는 별도 실험입니다. 기본 모드는 fixed이며 비교를 명시적으로 선택합니다.

1. 활성 동작이 없을 때, 160ms 이상·5프레임 이상의 안정 구간에서 TIP/관절 점수 중앙값을 동작 직전 기준으로 잡습니다. TIP/관절 점수 표준편차 한계는 각각 .10/.15입니다. 다음 갱신은 TIP이 현재 기준 + .20 이하인 구간에서만 허용합니다. 들림 중에는 기준을 고정합니다.
2. TIP 들림 .55·이동폭 .50·경로 .65는 유지합니다. 관절은 같은 방향 움직임의 보조 증거로 사용하며 최소 변화는 `max(.25, 2.5 * calibration_rest_angle_score_noise)`입니다. 관절 복귀는 동작 직전 기준 + .20 이하를 요구합니다.
3. 좌표가 계속 관측되는 경미한 국소 왜곡/보정 궤적 이탈은 최대 80ms 유예합니다. 국소 왜곡 ≤.50, 손바닥 대비 배율 .5~1.8, 그룹 점수 -.5~2, 잔차 ≤1.2를 모두 만족해야 합니다. 이 구간의 점수·궤적을 판정에 넣지 않고 후보를 발행하지 않습니다. 유예 시간은 들림 최소 시간에 포함하지 않으며 복귀 유지 시간을 다시 확인합니다.
4. 좌표 소실, 평가 손가락의 화면 이탈, 심한 왜곡, 긴 탈락은 즉시 취소합니다. 유예를 사용한 후보에는 `quality_hold_frames`를 표시하고 품질 휴리스틱을 .8배로 낮춥니다. 이 값은 교정된 확률이 아닙니다.

추적 실패나 동작 취소 후 `ready=False`가 되면 **이전 기준 + .20 제한 없이** 새로운 유효 안정 구간을 수집합니다. 160ms·5프레임·변동 한계를 통과한 뒤 이전 동작을 폐기하고 새 기준으로 준비합니다. 복구 자체나 첫 하강은 타건으로 세지 않으며, 새 들림→복귀가 필요합니다. 평상시 준비 상태의 낮은 구간 갱신 제한과 활성 동작 중 기준 고정은 유지합니다. `decision.reference`의 `state`, `recoveries`, `reacquired`, `updated_ms`로 복구 과정을 확인합니다.

이 예외가 없으면 이전 기준보다 높은 새 자세가 복귀 제한을 만족하지 못하고, 새 기준의 수집도 막는 고착 상태가 생길 수 있습니다. 실제 최근 10초 진단에서 이 상태를 확인했으며 보류 후 복구를 별도 회귀 테스트로 검증합니다. 타건·길이 임계값을 변경해 우회하지 않습니다.

### 2026-11-07: 시간 특징 필터와 기준 수집 개선

`local_baseline`은 최대 최근 5프레임·100ms의 TIP 특징, 관절각, 인접 길이, 손바닥 폭을 중앙값으로 처리합니다. 현재와 과거만 사용하며, `fixed` 비교 방식에는 필터를 적용하지 않습니다. 60 FPS에서 중앙 특징 시각은 대략 현재보다 33ms 이전입니다. `feature_filter.age_ms`와 이벤트의 `feature_filter_age_ms`로 이 지연을 별도 기록하며, 후보 시각을 실제 접촉 시각으로 보정하지 않습니다.

손 소실·필요한 영상 특징 유무 변경·100ms 초과 공백이면 이전 특징을 비웁니다. 평가 손가락의 화면 이탈, 원본 국소 왜곡 >.50, 원본 손바닥 대비 배율 <.25 또는 >3.6은 필터로 숨기지 않고 즉시 보류합니다. 정상 필터 출력에 대한 기존 길이 한계 .30 및 배율 .5~1.8은 유지합니다. `feature_filter.raw_valid`와 원본 점수·길이 사유를 함께 남기며, 원본 품질이 탈락한 프레임은 품질 휴리스틱을 .8배로 낮춥니다. 이는 검증된 확률 보정이 아닙니다.

기준 수집 중 경미한 품질 탈락은 최대 80ms까지 좌표를 제외하고 수집을 이어갑니다. 처음/복구 기준은 보정 TIP의 기준 쪽(기본 점수 ≤.50)에 가까운 구간에서 수집해 들림을 유지한 정지를 기준으로 받지 않습니다. 기존 기준이 있는 경우 상한은 `max(.50, reference_tip + .20)`입니다. 안정성은 `max(1.4826*MAD, IQR/1.349)`와 TIP 시작–끝 차이 ≤.20으로 확인합니다. 마지막 관측이 새 중앙값 대비 복귀 한계 안에 있을 때만 기준을 설치해, 기준 갱신 자체가 준비 상태를 풀어버리지 않도록 합니다.

약 13회를 수행했다고 알려준 601프레임 기록에서, 저장된 원래 결과와 구버전 재생은 3후보였으며 새 엔진은 11후보였습니다. 손 좌표는 575프레임에 존재했습니다. 정답 시각이 없으므로 11후보가 모두 맞거나 인식률이 11/13이라는 주장을 하지 않습니다. 개선에 사용한 기록의 개발 중 비교이며 별도 사용자·부정 시나리오 평가가 필요합니다. `engine_revision=2026-11-07-temporal-neutral-v2`로 실행 버전을 구분합니다.

```bash
python -m pthoven_tap replay --input ~/Downloads/pthoven-python-tap-capture.json --mode fixed --output outputs/fixed.json
python -m pthoven_tap replay --input ~/Downloads/pthoven-python-tap-capture.json --mode local_baseline --output outputs/relative.json
```

한 실제 10초 기록(600프레임)에서는 이전 입력 검사로 596프레임이 폐기됐습니다. 입력 검사 수정 후 fixed는 0후보, 상대 기준 실험은 5후보였습니다. 사용자가 기억한 동작 수는 약 7~8회이며 정확한 정답 시각은 없습니다. 이 결과는 해당 기록의 개발 중 비교 결과이고, 탐지율·정확도·일반화 검증 결과가 아닙니다. 원본 사용자 기록은 공개 저장소에 포함하지 않습니다. 정지·이웃 손가락·공중 탭·옆 끌기·가림의 실제 기록을 추가 평가해야 합니다.

`confidence`는 길이·잔여 오차의 품질 휴리스틱이며 교정된 접촉 확률이 아닙니다. 같은 관절 궤적으로 보이는 공중 탭과 책상 접촉은 구분되지 않을 수 있습니다. 이 한계는 테스트에도 명시합니다.

## Python 사용 예

```python
from pthoven_tap import calibrate, PoseTapDetector

model = calibrate(rest_frames, lift_frames, finger="index")
detector = PoseTapDetector({"index": model})
for frame in frames:
    result = detector.update(
        frame["t_ms"],
        frame["world_landmarks"],  # 21×3 또는 {x,y,z} 21개
        frame.get("landmarks"),  # 선택: 영상 정규화 좌표 21개
    )
    for candidate in result["events"]:
        print(candidate)
```

보정 입력은 21×3 배열의 리스트 또는 `{world_landmarks, landmarks}` 프레임 리스트를 받습니다. 실시간·재생 입력 시각은 비음수 ms이며 중복·역순을 허용하지 않습니다. Python 모델은 `algorithm=python_tip_angles_v1`로 구분됩니다.

## 웹 연결

H1 웹 실험실은 `/api/tap/reference`, `/api/tap/calibrate`, `/api/tap/session`, `/api/tap/frames`를 사용합니다. 카메라 접근·브라우저 MediaPipe SDK·그리기·파일 선택은 웹 연결부에 남아 있고, 판정 수학·보정·길이 검사·상태 머신은 이 Python 모듈에서 실행합니다. 서버 응답이 실패하면 JavaScript 판정기로 몰래 대체하지 않습니다. 기존 Depth 비교 실험의 레거시 로직 전체를 이 모듈로 변환한 것은 아닙니다.

개인 보정·평가를 사람/세션별로 나누고, 공중 탭·정지·옆 끌기·이웃 손가락·가림을 포함해 실제 카메라에서 검증해야 합니다. 자동 테스트 통과와 실제 사용자 탐지 정확도는 구분합니다.


### 2026-11-07: 알려진 기준 자세의 재확인

`engine_revision=2026-11-07-known-rest-v3`는 이전 기준이 있고 판정 준비만 풀린 경우, TIP/관절 점수 모두 이전 기준의 ±복귀 한계 안에서 최소 3개의 연속 유효 프레임과 기존 복귀 유지 시간(기본 40ms) 이상 확인되면 기준을 재사용합니다. 재사용 확인만으로 후보를 내지 않으며 중단된 동작을 이어 세지 않습니다. 확인 중 품질이 탈락하거나 한쪽 점수가 범위를 벗어나면 확인을 다시 시작합니다. 기준이 바뀐 경우는 기존 160ms 안정 구간 수집 경로를 유지합니다. 길이·들림·복귀·궤적 임계값을 낮추지 않았습니다. `decision.reference.reuses/reused`로 이 경로를 구분합니다.

두 시행이 담긴 추가 기록에서 사용자는 마지막 시행에 약 19회의 동작을 했다고 알려주었습니다. 마지막 시행의 저장/기존 재생 결과는 14후보였고 수정 후 재생은 16후보였습니다. 첫 시행은 2후보를 유지합니다. 두 시행을 합산하거나 후보 수를 정확도·재현율로 해석하지 않습니다. 마지막 시행 종료 시에는 들림 동작 하나가 진행 중이어서, 종료 경계 밖의 복귀는 판단할 수 없습니다. 실제 정답 시각은 별도 검수가 필요합니다.


## 다섯 손가락 적용 및 검증 범위

`FINGERS`의 엄지·검지·중지·약지·소지는 같은 보정·특징 필터·길이 검사·손가락별 상태 머신·기준 재확인 경로를 사용합니다. 고정된 검지 한 손가락에만 개선을 적용하는 구조가 아닙니다. 손가락별 보정 모델과 상태는 분리되어 있으며 한 손가락의 입력이 다른 손가락 후보로 바뀌지 않는지 검증합니다.

`tests/test_all_fingers.py`는 다섯 손가락 각각의 개인 보정, 반복 후보, 다른 손가락 상태와의 독립성, 다섯 손가락 동시 입력, 추적 소실 후 복구, 정지·전체 손 이동의 부정 사례를 합성 손으로 검사합니다. 이 합성 손은 사람 손의 해부학·가림·분절 협응을 재현한 데이터가 아니며, 엄지·약지·소지 등의 실제 성능을 증명하지 않습니다. 지금까지 전달받은 실제 타건 파일의 보정 모델은 검지뿐이므로, 다른 손가락의 실제 인식률은 별도로 수집·평가해야 합니다.

웹에서 전체 손가락을 사용하려면 같은 손 배치에서 기준 자세를 한 번 저장하고, 손가락 선택을 바꾸어 ‘선택 손가락 들림 저장’을 각각 수행합니다. 들림 보정을 추가하면 앞서 보정한 손가락도 유지됩니다. 기준 자세를 다시 저장하거나 추적할 손을 바꾸면 기존 손가락 보정이 초기화됩니다. 검지만 보정된 기존 JSON을 불러온 것만으로 나머지 손가락이 자동 보정되지는 않습니다.
